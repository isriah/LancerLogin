Modules and plugins

LancerLogin 2 is built from modules. Core always provides accounts, the roster, reports, integrations, backups, and updates. An Administrator chooses which modules to turn on.

ModuleHow it is includedWhat it does
AttendanceBuilt inMeetings, kiosk check-in and check-out, corrections, excuses, attendance rules, and kiosk management.
Outreach ParticipationOfficial plugin, included by defaultOutreach activities and participation hours submitted by members.
CarpoolOptional pluginRide planning to and from events.
Guest VisitsOptional pluginGuest visit records, which can also be counted in Outreach once an Administrator grants access.

Plugins are added to an installation from Settings › Modules › Manage modules or from the installation's private repository. See Add, update, or remove plugins.

How an installation fits together

  • Your private GitHub repository holds the deployment workflows and secrets. The public repository provides reviewed releases.
  • Your Cloudflare account runs the dashboard on Pages, the API on a Worker, and the data in a D1 database.
  • Each Raspberry Pi kiosk pairs with the dashboard and keeps an offline queue, so check-ins are saved while the network is down.
Community support is best-effort.Questions and responsible security or privacy reports can be sent to robolancers@gmail.com. There is no response-time or uptime commitment.

Release boundaries

  • An installation can pair several physical kiosks. The browser simulator is a software check, not a physical kiosk.
  • Dashboard updates and kiosk updates are separate steps.
  • Reports export as CSV. Backups are JSON files from Settings, or D1 exports for large installations.
  • This documentation never contains credentials, private repository details, attendance records, or backup contents.
