Task 3

Meetings, attendance, and reports

Role boundary

Operators manage meetings, attendance, corrections, excuses, reports, kiosk status, and can view the roster. Admins can also modify the roster, grant Admin/Operator credentials, and manage organization, security, integrations, privacy, updates, and destructive configuration.

Navigate and manage people

Home, Meetings, Attendance, Reports, Roster, and Kiosks are separate deep-linkable pages. Guided setup temporarily replaces dashboard content until complete, then remains available from Organization settings and Kiosks instead of occupying permanent navigation. Each Settings category has its own URL. On Roster, Admins may link a roster member to one dashboard account and assign Admin or Operator, or create a non-rostered staff account.

Run a meeting

  1. Create a one-time meeting or a bounded daily, weekly, biweekly, or monthly series with a title, start time, and required end time. Attendance windows cannot overlap, including the shared late-scan allowance.
  2. Search the Meetings table by any displayed attribute. Edit all fields for one occurrence or that occurrence and the future series.
  3. Each member scans on arrival and departure. The kiosk selects the eligible meeting automatically. One scan is active but not present; a complete pair is present. The organization-wide late-scan allowance defaults to 30 minutes after the end.
  4. Review absent records after scanning closes. Every correction or excuse requires a reason and creates an audit record.
  5. Monitor heartbeat, reader, pending queue, last sync, issue state, and installed release on Kiosks. Admins can use fixed display/service/reboot/PIN recovery actions there.
  6. Export all attendance as CSV whenever needed.

Import a roster safely

Upload or paste CSV on Roster, select Preview roster, and inspect the parsed table. Choose Add or update to retain people not in the file, or Replace active roster to deactivate omitted people. Replacement preserves historical attendance and dashboard credentials. No roster write occurs until the confirmation button is selected.

Optional communication workflows

R

Resend

Send one idempotent missed-meeting email or an individual attendance report to the email stored in the roster.

D

Discord attendance

Linked members can privately run /attendance-report. Every five minutes, eligible meetings can also notify only linked absent members after scanning closes. A signed recipient button opens a contest; an Operator reviews it with a required note before attendance can change.

K

Discord status/calendar

Upsert meeting calendar events. Authenticated heartbeats maintain one persistent kiosk-status message, and a five-minute reconciliation marks stale kiosks offline without blocking attendance.

Configure an optional integration

Open Settings → Integrations as an Admin. Open Google OAuth, Resend, or Discord for an official console link, exact callback value, required access, and guided verification. Fields appear immediately after the copy step that uses them. Saved secret values remain hidden, and a provider shows Configured only after end-to-end verification.

Register the Discord member commands

Discord registers application commands through its HTTP API. Create both commands at POST /applications/{application.id}/guilds/{guild.id}/commands, using the application ID and server ID from General Information and Discord. Authenticate the request with the saved bot token, but never paste that token into LancerLogin documentation, screenshots, chat, or a shared shell history. Guild registration makes the commands available only in the configured server.

Register /pair with this chat-input command payload:

{
  "name": "pair",
  "type": 1,
  "description": "Link your Discord account to your LancerLogin member ID",
  "options": [{
    "name": "member-id",
    "description": "Your LancerLogin member ID",
    "type": 3,
    "required": true
  }]
}

Register /attendance-report at the same guild endpoint with this payload:

{
  "name": "attendance-report",
  "type": 1,
  "description": "Privately view your current LancerLogin attendance report"
}

Discord treats a same-name POST in the same command scope as an update. After registration, finish LancerLogin's signed Discord verification in Settings → Integrations. Both commands return ephemeral responses; /attendance-report works only for the invoking Discord account's single active roster link and never accepts another member ID.

Review an available update

An Admin-only notice appears when a newer public release is available. Open Settings → Updates, read the patch notes, and download the required entire-installation backup. LancerLogin then opens the guarded workflow in the private deployment repository; choose Upgrade, keep Latest stable selected, and authorize the run there.

Back up, restore, delete, or reset

Settings → Data has independent backup, restore, and delete controls for Meetings and attendance, Roster, and Entire installation. Files restore only to their matching category. Entire-installation backups contain sensitive hashes and encrypted secrets, so protect them like administrator credentials. Reset onboarding clears only checklist progress. Attendance CSV protects spreadsheet formula markers as text. For files over 10 MiB or infrastructure recovery, use the repository’s token-neutral D1 helpers documented in docs/BACKUP-RESTORE.md.
