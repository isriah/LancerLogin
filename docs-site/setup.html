Task 1

Create your installation

Nothing in this flow uses or discovers another LancerLogin installation.

1. Link your Cloudflare account through GitHub

  1. Create or sign in to a Cloudflare account owned by your organization.
  2. In Cloudflare, create an API token restricted to Workers Scripts edit, D1 edit, and Pages edit for that account.
  3. In your new LancerLogin repository, open Settings › Secrets and variables › Actions and add the token as CLOUDFLARE_API_TOKEN. Never paste it into the dashboard.
  4. Open Actions › Provision adopter installation › Run workflow. Choose Create, enter a lowercase slug, and type CREATE <slug>.
  5. The workflow discovers the account from the token, refuses resource-name collisions, then creates D1, the Worker, and Pages. Open the stable Pages dashboard link from the workflow summary.

2. Create the first Admin

Choose local username/password, Google OAuth, or both. Local passwords require at least 12 characters and are stored as salted scrypt hashes. Google setup uses this callback:

Your Worker URL › /auth/google/callback

For Google, create a Web OAuth client in Google Cloud, add that exact authorized redirect URI, then save the client ID and secret under Optional integrations → Google OAuth. Saving again rotates the encrypted configuration; saved values are never displayed.

3. Finish the shared checklist

  1. Branding
  2. Roster (optional email and Discord user ID columns)
  3. Pair kiosk
  4. Fingerprint test
  5. Test meeting
  6. Attendance confirmation

Any Admin can resume the checklist. Once complete it hides, but remains reachable from Setup. Google, Resend, and Discord are separate and skippable.
