Troubleshoot

Fix a problem

Find the symptom below. When you ask for help, describe what you saw, but never send credentials, backups, or attendance records.

Installation workflow

When Install or upgrade LancerLogin or Refresh web update credential stops, the run's summary shows an error annotation whose title is one of these codes. Most checks run before anything is created or changed.

Error codeWhat it meansWhat to do
private_repository_requiredThe repository is public, or the update tokens do not belong to this private repository.Make the repository private, or create a private repository from the template. See Create your private repository.
operation_invalid, release_selection_invalidAn input is not one of the offered choices.Choose create, resume, or upgrade, keep latest stable, and run again.
installation_slug_invalidThe slug does not match the naming rule.Use 3 to 41 lowercase letters, digits, or hyphens, starting with a letter.
setup_code_required, setup_code_too_shortLANCERLOGIN_SETUP_CODE is missing or shorter than 16 characters.Add or replace the production environment secret with a longer password-manager value.
cloudflare_token_requiredCLOUDFLARE_API_TOKEN is not set.Create an account API token and store it as a production environment secret. See Create the Cloudflare API token.
account_token_requiredThe token is a user API token from My Profile. Account API tokens start with cfat_.Create the token under Manage account › Account API tokens and replace the secret.
account_token_invalid, cloudflare_token_rejectedThe token has expired, was revoked, or does not belong to CLOUDFLARE_ACCOUNT_ID.Create a new account API token in the right account and replace the secret.
cloudflare_account_id_invalidCLOUDFLARE_ACCOUNT_ID is not a 32-character account ID; often it is a zone ID.Copy the account ID again (step 4) and replace the secret.
cloudflare_permission_missingThe token lacks one of the four permissions. The message names it.Edit the token in Cloudflare to add the named permission, then run again.
cloudflare_request_failedCloudflare did not answer a read-only check.Check both Cloudflare secrets and run again.
workers_subdomain_requiredThe account has no workers.dev subdomain, so the API Worker would have no address.In Cloudflare, open Workers & Pages, set the account's workers.dev subdomain, and run again.
pages_address_takenAnother Cloudflare account already uses <slug>-dashboard.pages.dev, so Cloudflare gave the project a different address.Delete the <slug>-dashboard Pages project in your account if the run created it, then run create with a different slug.
pages_project_unavailableCloudflare did not return the Pages project.Run again with resume and the same slug.
installation_resources_existcreate found resources for this slug already in the account.Use resume to finish an interrupted installation, upgrade for an existing one, or another slug.
installation_not_foundresume found nothing for this slug.Check the slug, or run create.
installation_incompleteupgrade found the installation unfinished or missing resources.Run resume with the same slug to finish setup, then upgrade.
installation_database_missingThe Worker exists but its D1 database was not found. A new, empty database is never created for an existing Worker.Check LANCERLOGIN_DATABASE_NAME if you set it, and the slug.
release_invalid, release_identity_mismatchThe latest release could not be verified.Run again later.
dispatch_credential_required, dispatch_credential_access_denied, dispatch_credential_rejectedRefresh web update credential found LANCERLOGIN_WEB_UPDATE_TOKEN missing, without access to this repository, or expired or revoked.Create the token again as in Set up one-click updates, replace the secret, and run Refresh web update credential.
selection_credential_must_be_distinct, selection_credential_access_denied, selection_credential_rejectedThe optional plugin management token is the same as the update token, cannot read main, or has expired.Create a separate token with Contents: Read and write on only this repository and replace LANCERLOGIN_MODULE_SELECTION_TOKEN.
reviewed_workflow_required.github/workflows/upgrade-web.yml is missing or disabled.Restore and enable it on main.
fixed_account_resources_required, installation_slug_requiredThe installation variables are not set.Add LANCERLOGIN_INSTALLATION_SLUG, LANCERLOGIN_DATABASE_ID, and LANCERLOGIN_API_URL from the run summary. See Save the installation variables.
database_identity_mismatch, worker_database_mismatch, credential_target_unavailableThe variables do not match this installation's database and Worker.Copy the values from the installation run summary again.
credential_upload_failedCloudflare did not accept the Worker secrets.Check that the Cloudflare token has Workers Scripts: Edit, then run again.
token_expiration_unreadableGitHub reported a token expiry in an unexpected format.Run again later, and report it if it persists.

If a run stopped partway through for another reason, run the workflow again with operation resume and the same slug. Do not use create again.

First sign-in and access

What you seeWhat to do
The setup code is not accepted.Copy the LANCERLOGIN_SETUP_CODE value again without extra spaces. To use a new code, update the secret and run the workflow with operation resume. This works only while no Admin exists.
Google sign-in reports a redirect mismatch.Copy the callback address from LancerLogin into the Google client's Authorized redirect URIs exactly. See Google sign-in.
An account is locked after wrong passwords.Wait 15 minutes, or have another Admin set a new password in Settings › Access.
No Admin can sign in.Follow Recover access.
A page says Page unavailable.The page does not exist or your role cannot open it. Sign in with an account that has access, or ask an Admin to assign you to that module.

Kiosks

What you seeWhat to do
The phone cannot open http://<pi-hostname>.local:8788.Make sure the phone is on the same network as the Pi. Use the IP address the installer printed instead. On the Pi, hostname -I shows it.
Pairing says the key expired or the setup code is wrong.Create a new pairing key; each is valid for ten minutes. Enter the six-digit code currently shown on the kiosk screen. After five wrong codes the kiosk shows a new one and pauses pairing for a minute.
The attendance screen is closed.Open the LancerLogin Kiosk shortcut on the Pi desktop.
The kiosk shows offline or scans are waiting.Check the Pi's network with the network dot. Scans stay in the queue and send when the connection returns. Try Reload display, then Restart software, from Kiosks › Manage kiosk › Device maintenance.
Attendance is paused and the kiosk asks for the time.The Pi has no trusted clock. Choose Open maintenance, enter the PIN, and confirm the date and time.
A fingerprint is not recognized.Check that the member is active and enrolled on this kiosk. Without fingerprint sharing, enroll the member on each fingerprint kiosk. Test the reader in Authentication maintenance.
A kiosk update shows no result.Check the kiosk's status before trying again. If the new release failed to start, the kiosk has already switched back to the previous release.
Nobody knows the kiosk PIN.An Admin can choose Reset network PIN for that kiosk. The next person at the kiosk creates a new PIN.

For problems the dashboard commands cannot fix, someone with access to the Pi (in person, over SSH, or with Raspberry Pi Connect) can check the service:

systemctl status lancerlogin-kiosk.service --no-pager
journalctl -u lancerlogin-kiosk.service -n 30 --no-pager
curl http://127.0.0.1:8788/health

Keep this output private. Do not delete anything under /var/lib/lancerlogin, copy a queue to another kiosk, or pair a working kiosk again: waiting scans could be lost or counted twice. The kiosk reference covers recovery in more detail.

Dashboard updates

What you seeWhat to do
Updates cannot start because the update token is missing, expired, or revoked.Create a new token and run Refresh web update credential. See Set up one-click updates. You can also update without the token.
The update waits for approval.Choose Review approval in GitHub and approve the production deployment.
The update stops because a module moved into a plugin.Follow the choices on Settings › Updates to keep the module by adding its plugin, or to turn it off.
The update failed before it changed anything.Read the reason on the card, fix it, and start the update again with a new backup.
The card says recovery is required.Stop. Do not start another update and do not restore a backup. Open Diagnostics and manual recovery for the workflow run and contact support with what it shows.
A notice asks you to reload.The installation was updated. Choose Reload updated dashboard.

Integrations

An integration failure never undoes a meeting or attendance change, and it never stops kiosk scans. Open the integration's card in Settings › Integrations, read the reason it gives, correct the setting, and retry only that step. Changing a saved credential clears its verification until you verify again.

Backups and restores

  • A restore refuses a file from another category. Restore it on the matching card in Settings › Data.
  • A restore refuses a backup that contains a plugin this installation does not have. Add the plugin first, or confirm a restore that discards that plugin's data.
  • A large restore can fail with a message about database limits. Restore one category at a time, or use the D1 restore commands in the backup and restore reference.
  • After an entire-installation restore, pair every kiosk again.
