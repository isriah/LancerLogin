Troubleshoot

Fix a problem

Find the symptom below. When you ask for help, describe what you saw, but never send credentials, backups, or attendance records.

Installation workflow

When Install or upgrade LancerLogin or Refresh web update credential stops, the run's summary shows an error annotation whose title is one of these codes. Most checks run before anything is created or changed.

Error codeWhat it meansWhat to do
private_repository_requiredThe repository is public, or the update tokens do not belong to this private repository.Make the repository private, or create a private repository from the template. See Create your private repository.
operation_invalid, release_selection_invalidAn input is not one of the offered choices.Choose create, resume, or upgrade, and latest stable or latest beta, and run again.
beta_requires_upgradelatest beta was chosen with create or resume. A new installation always starts on a stable release.Run again with latest stable. To move an existing installation to a beta, see Update without the one-click token.
beta_track_requiredlatest beta was chosen for an installation on the Stable update track. Nothing was changed.Choose Beta in Settings › Updates › Update track and save it, then run again. To stay on Stable, choose latest stable.
release_downgrade_refusedThe installation already runs a newer release than the one chosen, usually a beta newer than the latest stable release. Nothing was changed.Wait for a newer stable release, or choose latest beta with upgrade.
installed_release_unreadableThe run could not read the installed release from the API Worker's /health address or from the Worker's settings in Cloudflare, so it could not rule out a downgrade. With latest beta the run stops. With latest stable it is a warning and the run continues, because that is also how a Worker that does not answer is repaired.For latest beta, open the address in the message to check that the Worker answers, then run again. For the warning, cancel the run if the installation runs a beta newer than the release being installed.
installation_slug_invalidThe slug does not match the naming rule.Use 3 to 41 lowercase letters, digits, or hyphens, starting with a letter.
setup_code_required, setup_code_too_shortLANCERLOGIN_SETUP_CODE is missing or shorter than 16 characters.Add or replace the production environment secret with a longer password-manager value.
cloudflare_token_requiredCLOUDFLARE_API_TOKEN is not set.Create an account API token and store it as a production environment secret. See Create the Cloudflare API token.
account_token_requiredThe token is a user API token from My Profile. Account API tokens start with cfat_.Create the token under Manage account › Account API tokens and replace the secret.
account_token_invalid, cloudflare_token_rejectedThe token has expired, was revoked, or does not belong to CLOUDFLARE_ACCOUNT_ID.Create a new account API token in the right account and replace the secret.
cloudflare_account_id_invalidCLOUDFLARE_ACCOUNT_ID is not a 32-character account ID; often it is a zone ID.Copy the account ID again (step 4) and replace the secret.
cloudflare_permission_missingThe token lacks one of the four permissions. The message names it.Edit the token in Cloudflare to add the named permission, then run again.
cloudflare_request_failedCloudflare did not answer a read-only check.Check both Cloudflare secrets and run again.
workers_subdomain_requiredThe account has no workers.dev subdomain, so the API Worker would have no address.In Cloudflare, open Workers & Pages, set the account's workers.dev subdomain, and run again.
pages_address_takenAnother Cloudflare account already uses <slug>-dashboard.pages.dev, so Cloudflare gave the project a different address.Delete the <slug>-dashboard Pages project in your account if the run created it, then run create with a different slug.
pages_project_unavailableCloudflare did not return the Pages project.Run again with resume and the same slug.
pages_api_binding_failed, in a warning titled Pages API binding not addedA warning, not a failure: Cloudflare did not connect the dashboard to the API Worker, and the message gives the HTTP status. The run continues and still deploys the dashboard, but sign-in limits are shared by all dashboard visitors.Check that the Cloudflare token has Cloudflare Pages: Edit, then run again with resume and the same slug. The next release update also adds the connection.
installation_resources_existcreate found resources for this slug already in the account.Use resume to finish an interrupted installation, upgrade for an existing one, or another slug.
installation_not_foundresume found nothing for this slug.Check the slug, or run create.
installation_incompleteupgrade found the installation unfinished or missing resources.Run resume with the same slug to finish setup, then upgrade.
installation_database_missingThe Worker exists but its D1 database was not found. A new, empty database is never created for an existing Worker.Check LANCERLOGIN_DATABASE_NAME if you set it, and the slug.
release_invalid, release_identity_mismatchThe latest release could not be verified.Run again later.
dispatch_credential_rejected, dispatch_credential_access_denied, dispatch_credential_check_unavailable, dispatch_credential_check_failed or token_expiration_unreadable, from Install or upgrade LancerLoginThe optional one-click update token in LANCERLOGIN_WEB_UPDATE_TOKEN has expired, was revoked, cannot read this repository, or could not be checked. For resume and upgrade this is a warning, not a failure: the run continues as if the token were not set and installs LancerLogin without it. Only create stops, before anything is created.Nothing is needed to finish the update. To turn one-click updates back on, create the token again as in Set up one-click updates, replace the secret, and run Refresh web update credential. To keep updating with the workflow instead, delete the secret, which also stops the warning. For create, replace or delete the secret and run it again. If resume or upgrade stops with one of these codes instead, your repository has a workflow file older than v2.1.0-beta.10: delete the secret and run again, or update the workflow file by hand.
dispatch_credential_required, dispatch_credential_access_denied, dispatch_credential_rejectedRefresh web update credential found LANCERLOGIN_WEB_UPDATE_TOKEN missing, without access to this repository, or expired or revoked.Create the token again as in Set up one-click updates, replace the secret, and run Refresh web update credential.
selection_credential_must_be_distinct, selection_credential_access_denied, selection_credential_rejectedThe optional module management token is the same as the update token, cannot read main, or has expired.Create a separate token with Contents: Read and write on only this repository and replace LANCERLOGIN_MODULE_SELECTION_TOKEN.
reviewed_workflow_required.github/workflows/upgrade-web.yml is missing or disabled.Restore and enable it on main.
fixed_account_resources_required, installation_slug_requiredThe installation variables are not set.Add LANCERLOGIN_INSTALLATION_SLUG, LANCERLOGIN_DATABASE_ID, and LANCERLOGIN_API_URL from the run summary. See Save the installation variables.
database_identity_mismatch, worker_database_mismatch, credential_target_unavailableThe variables do not match this installation's database and Worker.Copy the values from the installation run summary again.
credential_upload_failedCloudflare did not accept the Worker secrets.Check that the Cloudflare token has Workers Scripts: Edit, then run again.
token_expiration_unreadableGitHub reported a token expiry in an unexpected format.Run again later, and report it if it persists.

If a run stopped partway through for another reason, run the workflow again with operation resume and the same slug. Do not use create again.

First sign-in and access

What you seeWhat to do
The setup code is not accepted.Copy the LANCERLOGIN_SETUP_CODE value again without extra spaces. To use a new code, update the secret and run the workflow with operation resume. This works only while no Admin exists.
Google sign-in reports a redirect mismatch.Copy the callback address from LancerLogin into the Google client's Authorized redirect URIs exactly. See Google sign-in.
Sign-in says Too many sign-in attempts. Wait a few minutes before trying again.Too many sign-ins were tried from your network in ten minutes. Wait and try again. If this happens to a whole team at once after updating to 2.1, see the "Pages API binding not added" note in Updating from LancerLogin 2.0 to 2.1.
A message says This page is out of date. Reload the page and try again.The tab was opened before the installation was updated. Reload the page. On the sign-in page the same cause shows as "Invalid username or password".
An account is locked after wrong passwords.Wait 15 minutes, or have another Admin set a new password in Settings › Access.
No Admin can sign in.Follow Recover access.
The dashboard shows Setup service unavailable or Session check unavailable.LancerLogin could not reach its server, or the server took longer than 15 seconds to answer. Check your connection and choose Try again.
A page says Page unavailable.The page does not exist or your role cannot open it. Sign in with an account that has access, or ask an Admin to assign you to that module.

Kiosks

What you seeWhat to do
The phone cannot open http://<pi-hostname>.local:8788.Make sure the phone is on the same network as the Pi. Use the IP address the installer printed instead. On the Pi, hostname -I shows it.
Pairing says the key expired or the setup code is wrong.Create a new pairing key; each is valid for ten minutes. Enter the six-digit code currently shown on the kiosk screen. After five wrong codes the kiosk shows a new one and pauses pairing for a minute.
The attendance screen is closed.Open the LancerLogin Kiosk shortcut on the Pi desktop.
The kiosk shows offline or scans are waiting.Check the Pi's network with the network dot. Scans stay in the queue and send when the connection returns. Try Reload display, then Restart software, from Kiosks › Manage kiosk › Device maintenance.
Attendance is paused and the kiosk asks for the time.The Pi has no trusted clock. Choose Open maintenance, enter the PIN, and confirm the date and time.
A fingerprint is not recognized.Check that the member is active and enrolled on this kiosk. Without fingerprint sharing, enroll the member on each fingerprint kiosk. Test the reader in Authentication maintenance.
A fingerprint kiosk shows Scan again.The read was faint or smudged, or the same member was recorded at a different kiosk less than 30 seconds before. The member places the same finger flat and holds it still; wipe the reader if it keeps happening. Nothing was recorded for the refused scan. See Scan checks.
A kiosk adds Your fingerprint is reading weakly. Ask a mentor to re-enroll it.Attendance was recorded. Enroll the member's finger again in Authentication maintenance when convenient. With Debug mode on, Re-enroll suggested under Debug tools on the Kiosks page lists these members.
A web kiosk says This kiosk needs pairing again.The server no longer accepts its pairing: the kiosk was retired, replaced, or the installation was restored from a backup. Create a new code from Kiosks › Add kiosk › Web kiosk and enter it on the device. See Pair a web kiosk.
A web kiosk opens on the pairing screen although it was paired.The browser lost its storage: a private window, cleared site data, or on an iPad a page not added to the Home Screen. Pair it again, then install the kiosk page as an app.
A web kiosk footer shows Offline and a number waiting.Check the device's Wi-Fi. Scans are saved on the device and sent when the connection returns, so leave the page open and do not unpair it or clear the site's data while scans are waiting. Discord codes do not work offline; members use the backup method.
A kiosk shows Please wait after a PIN.Five wrong PINs in a row were entered for that member. The kiosk says when to try again: 30 seconds, then 1 minute, then 5 minutes between tries. An Admin or Operator can choose Unlock, or Reset PIN for a forgotten PIN, on the Kiosk PIN card of the member's Roster page.
A Discord code is refused, or the kiosk shows Code not recognized.The code was mistyped, has expired (codes last 2 minutes), or was already used for a recorded scan. The member runs /code again. A scan refused for another reason, for example with Too early, does not use the code up. A member who gets no code needs their Discord account linked with /pair.
A Raspberry Pi kiosk shows Discord codes are paused while earlier scans sync.Scans the kiosk saved earlier are still waiting to be sent, and a code is never sent ahead of them. Members sign in with the backup method shown; the code screen returns by itself once the waiting scans have synced. If it stays, check the kiosk's network.
A web kiosk shows This kiosk hit a problem.Choose Reload kiosk. The kiosk stays paired and scans waiting to sync are kept.
Require PIN is greyed out, and the notice below it says "Update this kiosk to use Require PIN".The Raspberry Pi kiosk has not reported release 2.1.0-beta.3 or later, the first release that asks for PINs. Update the kiosk, wait for it to check in, and open Manage kiosk again. From 2.1.0-beta.10 a Pi kiosk reports its release when it pairs, so Require PIN works right after pairing. An older kiosk that was paired a moment ago reports it at its first check-in: check Installed release under Diagnostics, and reload the page after a few seconds.
Update kiosk says GitHub is limiting release checks right now.Nothing is wrong with the kiosk, and no update was started. GitHub allows only a limited number of unsigned release checks each hour, and your installation shares that allowance with other sites on Cloudflare. Wait for the time the message gives, then choose Update kiosk again. To avoid the limit, set up one-click updates: release checks are then signed with its token.
Update kiosk says GitHub did not answer, could not be reached, returned an error, or gave an answer that could not be read.Nothing is wrong with the kiosk, and no update was started. Try again after the time the message gives.
Update kiosk says the release list has no complete official kiosk release on your update track.No kiosk release is available on that track yet, so there is nothing to install. Try again after the next release is published.
A kiosk update shows no result.Check the kiosk's status before trying again. If the new release failed to start, the kiosk has already switched back to the previous release.
Nobody knows the kiosk's network or settings PIN.An Admin opens the kiosk's Manage kiosk page and chooses Reset network PIN (Reset settings PIN on a web kiosk) under Device maintenance. The kiosk must be online. The next person at the kiosk creates a new PIN.
A member chose Ask for approval to set a PIN and is still waiting, or the kiosk shows Request expired.An Admin or Operator approves the request in the dashboard, from the PIN requests button at the top of any page or from PIN requests on Manage kiosk. After Request expired or Approval ran out, the member asks for approval again. See Approve and reset kiosk PINs.

For problems the dashboard commands cannot fix, someone with access to the Pi (in person, over SSH, or with Raspberry Pi Connect) can check the service:

systemctl status lancerlogin-kiosk.service --no-pager
journalctl -u lancerlogin-kiosk.service -n 30 --no-pager
curl http://127.0.0.1:8788/health

Keep this output private. Do not delete anything under /var/lib/lancerlogin, copy a queue to another kiosk, or pair a working kiosk again: waiting scans could be lost or counted twice. The kiosk reference covers recovery in more detail.

Dashboard updates

What you seeWhat to do
Updates cannot start because the update token is missing, expired, or revoked.Create a new token and run Refresh web update credential. See Set up one-click updates. You can also update without the token.
The update waits for approval.Choose Review approval in GitHub and approve the production deployment.
The update stops because a module moved into a plugin.Follow the choices on Settings › Updates to keep the module by adding its plugin, or to turn it off.
The update failed before it changed anything.Read the reason on the card, fix it, and start the update again with a new backup.
A re-run of the update's GitHub workflow run fails with request_not_claimable.Re-running a run never retries an update, and nothing was changed. Start the update again from the dashboard, or choose Apply changes for a plugin change.
The card says recovery is required.Stop. Do not start another update and do not restore a backup. Open Diagnostics and manual recovery for the workflow run and contact support with what it shows.
A notice asks you to reload.The installation was updated. Choose Reload updated dashboard.

Integrations

An integration failure never undoes a meeting or attendance change, and it never stops kiosk scans. Open the integration's card in Settings › Integrations, read the reason it gives, correct the setting, and retry only that step. Changing a saved credential clears its verification until you verify again.

Backups and restores

  • A restore refuses a file from another category. Restore it on the matching card in Settings › Data.
  • A restore refuses a backup that contains a plugin this installation does not have. Add the plugin first, or confirm a restore that discards that plugin's data.
  • A large restore can fail with a message about database limits. Restore one category at a time, or use the D1 restore commands in the backup and restore reference.
  • After an entire-installation restore, pair every kiosk again.
