## External acceptance boundary

No existing attendance installation, Cloudflare resource, Raspberry Pi, credential, database, repository, or git history was modified or reused. The community collector remains in its collector-only account. On 2026-08-31 the user explicitly approved a narrower exception allowing a coexistence deployment in the same Cloudflare account as the earlier attendance resources. A new least-privilege seven-day token and the collision-guarded Create workflow produced only `lancerlogin-test-api`, `lancerlogin-test-data`, and `lancerlogin-test-dashboard`; no custom domain, route, binding, migration, or shared data path was created. The isolated Create acceptance passed, the Pages dashboard rendered the fresh first-Admin setup, `/api/health` returned ready, and `/api/setup/status` returned unconfigured. The isolated Upgrade acceptance subsequently validated those exact resources and retained secret names, applied all migrations, and redeployed only that Worker and Pages project. At the user's request, the public deployment workflow runs and their logs/artifacts were permanently deleted on 2026-09-01; this durable record intentionally does not link to removed run pages. Live browser smoke tests confirmed the guided setup wizard, dark-mode branding access, and simulated-kiosk path. Physical Pi/R503 acceptance remains pending.

CI and every tagged release run `npm run verify:migrations`, which creates an isolated local D1 database, applies every numbered migration in order, compares the applied list to the source directory, inspects the final themed-branding and kiosk-health schema, checks the biometric-storage invariant, and removes the generated state. It never uses a Cloudflare token or remote flag.

The v0.4 private-deployment release remains intentionally undeployed until its tag is published and the private repository is configured. No dashboard-triggered deployment exists.
