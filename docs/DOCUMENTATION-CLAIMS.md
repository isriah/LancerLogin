# Private claims and versioned definitions

Dependencies: WU145 Documentation authority, WU147 initiatives, WU149 metric histories and WU151 artifact histories; WU154 API ownership released. WU155 adds metadata only. No official definition is seeded, source URL fetched, file copied, metric summed or claim automatically classified as award-compliant. Packet selection/publication, UI and member intake are separate subsequent work.

## Definition and claim APIs

All routes require current active Admin or documentation.manage with both modules enabled. Attendance Operators and Hours-only staff gain no access. Built-in notes, Files and summaries switches do not disable independent claims/definitions. All input is bounded plain text. Current account/grant/modules, optimistic revision and new association eligibility are fenced in the same mutation statement; a request-specific admitted audit gates the immutable snapshot and link inserts in its transaction. Audit metadata contains no rationale, definition text or evidence content.

Definitions: `/admin/documentation/definitions` GET lists `{definitions,next}`; POST accepts `{title,definition,source?}` and returns201 `{definition}`. PATCH `/:id` accepts revision plus changed title/definition/source/archived and returns `{definition}`. GET `/:id` returns `{definition,readOnly}`. Definition DTO has id, title, definition, source, archived, revision, authorUserId, createdAt and updatedAt. Each revision preserves all text and provenance. An archived definition permits only `{revision,archived:false}` before a separate edit. No hard deletion is exposed.

Claims: `/admin/documentation/claims` POST requires `{title,definitionId,definitionRevision,periodStart,periodEnd}`; optional rationale defaults empty and five association arrays default empty. PATCH `/:id` accepts revision plus changed fields, associations or archived. POST returns201 and PATCH200 `{claim}`. Claim DTO has id, title, definitionId, definitionRevision, periodStart, periodEnd, rationale, archived, revision, immutable authorUserId/createdAt, updatedAt and review. Archived claims permit only `{revision,archived:false}`. No record or Hours total is duplicated by an association.

GET `/:id` returns `{claim,definition,activities,teams,initiatives,artifacts,metrics,readOnly,dependencyChanged,incompleteness}`. The selected definition includes immutable text/source/revision, currentRevision and current archive/changed flags. A claim always names a real selected definition revision; selecting an older nonarchived definition revision is permitted while its definition remains active. Existing selection survives definition edits/archive.

GET claims prefix returns `{claims,next}`; each list item uses the same envelope as detail, with compact evidence summaries. List and detail metadata, reference status and current authority share one SQL query. `incompleteness` is `{rationaleMissing,contextsMissing,evidenceMissing}`. Empty rationale, standalone claims and no evidence are allowed, including explicit review; these flags communicate omissions without inventing eligibility or compliance rules.

## Explicit review and pinned evidence

POST `/claims/:id/review` accepts `{revision,decision:reviewed|rejected}` and returns `{claim}`. It advances the claim revision and stores a complete immutable snapshot plus a dedicated review record pinning the pre-review revision. Review DTO is null or `{decision,reviewedRevision,reviewerUserId,reviewedAt}`. Concurrent reviewers using one revision cannot both succeed. Later claim metadata, association, archive or unarchive edits clear the current review; history preserves prior decisions exactly. An artifact's own review is independent and is not required for claim review.

Context arrays are `activities:[{activityId,revision}]`, `teams:[{teamId,revision}]`, and `initiatives:[{initiativeId,revision}]`. New or changed context pins require that current revision and an active eligible target: impact-relevant activity, active supported team or active initiative. Existing exact pins remain readable/removable after target edits, archival or relevance loss. Selecting an initiative never expands its activities automatically. Context labels are current names, not historical title snapshots; retained target_revision records the revision observed when selected, without fabricating unavailable Hours history.

Evidence arrays are `artifacts:[{artifactId,revision,currentRevision?}]` and `metrics:[{metricId,revision,currentRevision?}]`. `revision` identifies an existing immutable history row, including an explicitly selected older revision. Every new/changed evidence pin requires `currentRevision` equal to the current active parent record in the admission transaction. Unchanged retained pins may omit it. No pin is automatically refreshed. Duplicate target identities within a type are rejected; at most100 links total across all five arrays. Supplied arrays fully replace that type for the new claim revision; omission copies previous memberships.

Each association DTO contains its type-specific ID, selected revision, currentRevision, title/currentTitle, eligible, changed and currentArchived. Artifact/metric evidence additionally has selectedArchived from the pinned history row; context records have no historical archive snapshot. Artifact/metric title is the pinned title and currentTitle is the live title. Context title/currentTitle are both current names. Artifacts expose `selectedReview` from their pinned revision independently of claim review. Detailed artifact snapshots also include caption, URL and originalUrl; no preview or request is performed. Metric summaries preserve kind, exact decimal value/scale, unit, periodStart/periodEnd and measured/estimated basis; detail additionally includes pinned source/method. Participants are not inferred unique, and overlapping initiatives are never summed.

`dependencyChanged` flags selected definition or linked target revision/archive/relevance differences from current state. It accompanies historical review and never rewrites a reviewed snapshot or declares claim validity. Later export work must present/review its own selections; this backend does not publish.

## Selectors, history and bounds

`GET /admin/documentation/teams` provides a narrow active supported-team selector: `{teams:[{id,name,number,organization,program,revision,archived:false}],next}`. It does not expose historical descriptors, Hours descriptions, roster IDs or contact data and does not grant Hours catalog management. Existing claim links supply archival team labels through claim reads/history. Existing Documentation activity/initiative/artifact/metric selectors remain their own contracts.

Lists use `limit`1-50 (default25), opaque after-ID and `archival=true` to include archived definitions/claims. Histories use integer after-revision and the same page limit. GET `/definitions/:id/history` returns `{definitionId,authorUserId,createdAt,revisions,next}`; rows contain definition text/source/revision/archive, actorUserId and revision creation time. GET `/claims/:id/history` returns `{claimId,authorUserId,createdAt,revisions,next}`; each row has claim field projection and actorUserId plus the nested `claim`/definition/association/status envelope used by list reads. Revision rows have no authorUserId or updatedAt; original author/time comes from the enclosing history header. The nested claim's createdAt is that revision's time. Consumers must not invent header-only fields. History membership and evidence values remain pinned; current context labels/status are explicitly live projections. Compact history evidence omits artifact caption/URLs and metric source/method. For the current claim, detail supplies these exact pinned fields. For a historical claim pin, read the existing artifact/metric `/:id/history?limit=1&after=N-1` endpoint and require the returned revision to equal N (omit after for N=0). Those immutable history rows contain the pinned fields even when the parent has changed or archived. Never substitute the current artifact/metric metadata for that selected revision.

Technical defaults: titles1-200, definition1-8000, optional rationale0-8000 and source0-2000 UTF-16 code units; tab/newline allowed, other control characters rejected. Inclusive real ISO dates1900-01-01 through9999-12-31 with start<=end. UTF-8 JSON requests are bounded to120000 bytes. Errors use existing sanitized400/401/403/404/405/409 responses. Reload after conflict or uncertainty; do not automatically retry a mutation.

## Portable and raw recovery

Migration0044 adds ten tables: definition/claim headers and revisions, five typed immutable claim revision-link tables and review records. Current membership derives from the header revision. Artifact/metric/definition pins use real installation-scoped revision foreign keys; other context pins use real scoped catalog foreign keys. There are no fake files, definitions or polymorphic unchecked target IDs.

Portable backup25 includes all ten tables; versions1-24 normalize them empty. Validation checks exact complete revision chains, actor/creator/time consistency, real same-installation references and selected history revisions, duplicate/combined link limits, current header equality, pure unarchive membership retention, and exact review snapshot/provenance equality before destructive restore. Inactive historical authors are retained. Attendance-only restore preserves all claims/definitions. Backup validation establishes structural consistency, not authenticity of a manually edited backup.
