# Preserved Drive source intake (WU165 implementation contract)

Dependencies: central isolated drive.file Picker, verified organizational private root, WU161 original validation and WU162 artifact/upload inventory. Runtime, schema48 and backup28 have local fixture verification. Hosted copy acceptance and the separately owned WU166 interface remain separate gates.

Staff with current Documentation management may select a source through the central Picker using the separate `documentation-source` purpose. The intent remains bound to the current staff session, organizational generation and connection revision. Existing Admin root/synthetic selection remains unchanged. Selection requires an exact accessible file, canCopy, source version and MIME; folders and shortcuts are not originals. Native Google files retain their native type. Binary intake retains the provisional 4 MiB boundary and rejects larger files before copying. No broader Drive grant, pasted-URL retrieval or export-to-fake-original is permitted.

POST `/admin/documentation/drive-copies` accepts sourceIntentId, title, caption, sectionRevision, activity/initiative current-revision associations and idempotencyKey. It consumes the selected intent atomically with current staff/module/Files/context authority and records the original private root, root revision, organizational generation, source identity/version and exact admitted metadata. Subsequent GET list/status and explicit POST advance/reconcile operate on the same immutable operation. Source resource keys are encrypted transient authority, excluded from portable backups.

Artifact responses add `kind: preserved-drive` and `preservedDrive: {id,rootId,generation,mime,sourceId,sourceVersion,copiedAt,validation:{outcome}}`. Native outcome is `native` with no invented byte length or SHA-256. Bounded binary outcomes are `embedded` or `linked-only`, with exact byteLength and sha256, after existing isolated compute validation. Existing external-link and uploaded-file responses do not change. Immutable artifact revisions retain the preserved-copy provenance. Metadata editing does not replace the preserved original.

Before files.copy, validate source version, private owner-only destination and current authority, then durably record dispatch. The request assigns an exact operation appProperty and private parent. An uncertain result is reconciled by that exact marker and parent; zero or multiple matches remain unresolved and never trigger another copy. Recheck source version after copying and verify destination identity, MIME, parent, owner-only permissions and binary checksum before artifact creation. Native copies use native provider identity/version evidence, not a synthetic content hash. External owner edits are not atomic with the application; changed source or ownership leaves explicit reconciliation rather than a successful artifact.

Schema48 must preserve existing artifacts, immutable revisions, memberships and claim pins while adding the discriminated metadata and durable operation inventory. Backup28 must retain original/destination identity and provenance, discard live credentials/leases, and restore dispatched incomplete copies as reconciling without resuming provider actions. Installation replacement must not discard known or ambiguous remote ownership. Database backup does not copy Drive binaries or native documents.

Focused acceptance covers current Documentation Staff authority versus denied Hours/Operator, session/purpose selection isolation, source/root/section changes, native and bounded binary successful preservation, rejected binary validation before copy, source metadata size limits, lost acknowledgement with exactly one copy per operation, unresolved zero/multiple marker matches, preserved revision/claim references and backup restoration. Existing upload behavior remains compatible. External resources, real provider calls, deployment and P5 implementation are outside this local unit.

The central Picker paths remain under `/admin/connections/google/drive`: GET `/status?purpose=documentation-source`, POST `/picker/authorize` with revision and purpose, POST `/picker/claim` with revision/intentId, and POST `/selection` with revision/intentId/fileId/optional resourceKey. A consumed product callback returns to `/documentation?drivePicker=ready|failed`. Staff cannot configure the Picker, select its Admin root/synthetic purpose, or run feasibility experiments. Product and Admin status/authorization sessions are isolated.

Copy admission returns HTTP 202 with `{reference,title,state,saved,artifactId,requiresReconciliation,error?}`. States are ready, validating, reconciling, saved and failed. GET `/admin/documentation/drive-copies?after=...&limit=25` returns `{operations,next}`; GET `/:reference` returns the operation. Explicit POST `/:reference/advance` or `/:reference/reconcile` accepts `{}` and returns HTTP 202 with its current operation. No automatic job schedules a copy. Reuse the original admission key after an uncertain receipt; never infer a new dispatch from zero reconciliation matches. All binary byteLength/sha256 fields are at the `preservedDrive` root; `validation` contains only outcome. Native originals omit byteLength/sha256.

Binary intake reads at most 4 MiB and validates retained original bytes through isolated compute before dispatch. A two-minute lease serializes the bounded phase; session expiry caps the lease. Reconciliation may rebind a reverified connection revision only for the original root and organizational generation. Source change/deletion before successful artifact creation leaves the operation unresolved. Source deletion after a saved copy does not remove that artifact. Database restore strips resource keys and leases; unsent work becomes failed, while dispatched incomplete work remains reconciling. Lost source resource-key authority may require operational recovery; restore never invents it or repeats files.copy. Private Drive originals themselves are not in the database backup.

Verification: five source/copy/Picker/intake tests passed; five existing artifact/claim/upload D1 tests passed; populated migration48 preserves prior binary metadata, immutable history and claim pins; the fresh migration command verified all 48 migrations; API typecheck passed. These are local fakes and D1 evidence, not provider or integrated UI acceptance. Backup schema assertions in other existing fixtures advance mechanically to28; their broad suites were not rerun for this checkpoint.
