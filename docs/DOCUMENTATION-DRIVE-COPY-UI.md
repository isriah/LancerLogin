# Staff preserved Drive copy interface

Dependencies: WU165 preserved Drive copy API, central `documentation-source` Picker purpose, current Documentation management and Files section authority. This interface adds no provider credentials or Admin connection configuration.

The Documentation **Drive copies** view returns from `/documentation?drivePicker=ready|failed`, reads the scoped selection, and uses the existing isolated Picker claim lifecycle. Staff select one source, enter title/caption and optional current-revision associations, and explicitly admit a preservation operation. Picker tokens remain in memory and are cleared when Picker closes. Access checks close the Picker; grant removal is handled by the existing workspace access boundary.

Admission serializes and freezes the complete request and its random idempotency key before sending. An ambiguous response offers only an explicit retry of those same bytes. Once an operation reference is known, Check uses GET; Continue and Reconcile explicitly advance that reference. There is no polling or automatic second copy. Once an operation reference is confirmed, Documentation navigation is available and the paginated inventory supports recovery. A confirmed failed-before-dispatch operation permits choosing a different original; reconciling operations never offer replacement. Keep the page open for recovery of an admission whose reference has not been acknowledged; browser storage does not persist the request or credentials.

Saved copies appear in Artifacts with immutable original URL and source/version/copy-time provenance, including immutable history. Native copies have no fabricated byte length or checksum. Binary validation uses root-level byteLength/sha256 and validation.outcome from the API. Metadata changes omit the immutable URL. Preservation, validation, staff review and publication are distinct outcomes.

Design planning/review: reused `hours-stack`, `hours-actions`, `hours-check`, `ui-card`, `ui-status`, and the existing fieldset/input/textarea treatment. These inherit font-body/font-display, text heading roles, space tokens, radius-card/control, control-min-block-size, and semantic ui surface/text/border/focus colors. No CSS, new tokens or standard exceptions. One page h1, nested section headings, labeled native controls, centered action rows, 44px controls and one primary admission action. Light/dark screenshots at 1280x900 and 390x844 with purple/teal adopter branding were inspected; no page overflow or clipping. The existing tall mobile Documentation view navigation remains outside this unit.
