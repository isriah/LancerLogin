# Initial release: attendance and Hour Tracking

WU202 fixes the shipped release capability in `packages/shared/src/release-capabilities.ts`: Activity Documentation is unavailable. It is not a runtime environment flag or an Admin setting. Core attendance and optional Hour Tracking remain available. Documentation implementation, migrations and retained data remain in the repository and full-schema backup/restore model.

Module snapshots and grant reads expose only available capabilities without changing stored rows. Admin requests cannot enable Documentation or add its grant. An explicit module configuration save normalizes its old enabled flag to zero, including when Hours is disabled, so a dormant Documentation flag cannot violate the existing dependency constraint. Staff grant edits preserve the stored Documentation grant. Structural backup validation continues to accept complete historical module configurations and grants; it does not reuse release-availability rejection. No migration or mass data update is added.

The API rejects Documentation public/admin paths and dedicated Google Drive storage/Picker paths, including Picker callback dispatch. Documentation Discord commands, stale components and development attachment-proof commands cannot start their workflows. Command reconciliation omits their registration. Development compute/attachment proof HTTP routes are also unavailable. Public-note submission, upload admission/advance and Drive-copy admission have explicit gates, and the shared Google Drive capability cannot issue provider access in this release. Calendar and staff Google sign-in remain separate capabilities. Existing provider receipts and backup ownership inventories remain intact; this release does not silently reconcile or delete old ambiguous work.

The current scheduler contains attendance, Hours and core jobs, not executable Documentation jobs. A future Documentation job must use the release availability admission as well as its installation enablement. Already-running executions from older deployed code remain subject to the updater's independent maintenance/adoption requirements; a source constant does not prove that deployed work has drained.

Dashboard module settings and grants accept the available module set, Documentation navigation and direct public form entry are unavailable, and Google setup omits Drive purpose/consent/storage controls. Existing semantic fieldsets, controls, layout, fonts and color tokens are reused without CSS changes or standards exceptions. Existing stored provider scopes may still be shown accurately; they do not grant an available Documentation capability.
