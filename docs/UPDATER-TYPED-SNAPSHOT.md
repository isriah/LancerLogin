# Typed snapshot capture foundation

WU181 captures schema-49 application D1 rows as encrypted, typed pages. A completed capture is a `snapshot-candidate` with **`verified: false`**. It is not an engine backup adapter, SQL import, logical API backup or validated restore. WU176's original SQL export remains a separate candidate.

## Reviewed schema catalog

`node scripts/generate-snapshot-catalog.mjs` executes exactly the 49 trusted local migration files on an empty, disposable local SQLite database and emits `apps/updater/src/snapshot-catalog.mjs`. It copies no application records. The generated catalog contains the migration ID/digest chain, its SHA-256, final schema objects and fixed table/column lists. Its separate catalog digest is checked by the portable consumer. Generated code belongs to the trusted updater bundle; there is no browser-supplied catalog or executable SQL from snapshot contents.

The catalog covers **99 tables and 281 schema objects**, including explicit/automatic indexes and triggers. Native `d1_migrations` and `sqlite_sequence` are explicit: the native schema matches the inspected Wrangler 4.127.1 `getCreateMigrationsTableQuery`, including nullable `name TEXT UNIQUE`. Catalog chain digest is `0b0ee908bd191ea75e3c22da5f7d7a259ee51640bfeb6644990ddcae682648b4`; catalog digest is `fbb5cdf36fc559b55380d07f370ae0652e7d80a35ac72a6850133a3825247407`.

Live schema is compared exactly before and after capture, and native ordered migration names must equal the catalog chain. Unknown application objects reject capture. Cloudflare's `_cf_KV`/`_cf_METADATA` and their indexes are excluded explicitly; SQLite statistics/internal objects are excluded except automatic indexes and `sqlite_sequence`. A different native-schema formatting/version or another schema version requires a separately reviewed catalog rather than permissive normalization. The generator rejects hidden/generated columns, WITHOUT ROWID/virtual tables and shadowed rowid aliases. Existing catalog tables support ordinary SQLite rowid keyset pagination.

WU195 adds compiled intermediate catalogs and replay plans for schemas 47 and 48. Both generators accept only `--schema 46`, `--schema 47`, `--schema 48` or `--schema 49`; omitted arguments still generate schema 49. Run `node scripts/generate-snapshot-catalog.mjs --schema 47` followed by `node scripts/generate-snapshot-replay-plan.mjs --schema 47` (or substitute 48). These emit the corresponding `snapshot-catalog-47.mjs` and `snapshot-replay-plan-47.mjs` files. Existing schema-46 and schema-49 generated bytes are unchanged.

Trusted constructors may explicitly select `catalogKey: 'schema-47-v1'` or `'schema-48-v1'` through the static registry. The default remains `'schema-49-v1'`. These artifacts supply exact DDL, native migration names, trusted migration digests and replay ordering for a later current-schema identifier. They do not implement automatic identification: capture still requires a preselected catalog and matching trusted schema/ledger authority. A future identifier must compare the complete primary schema and native ledger with the compiled catalog and corroborate migration provenance using trusted job/receipt evidence; native migration names alone do not prove signed hashes. Partial or unrecognized schemas remain unresolved. No runtime bootstrap, recovery or application restore is wired by this addition.

## Lossless typed values and bounded projection

Each page encodes a fixed table name, ordered columns, and rows shaped as `[rowidDecimal, cells]`. Cells are tagged arrays: `['null']`, `['integer', decimal]`, `['text', hexBytes]`, `['blob', hexBytes]`, or `['real', decimal]`. Integers and pagination keys never pass through JavaScript numbers; signed 64-bit extrema and negative rowids remain decimal strings. Text uses its original SQLite byte representation, preserving NUL and UTF-8 bytes without JSON string conversion. Empty text and empty BLOB remain distinct.

REAL projection uses SQLite `printf('%!.26g', value)` only when the value is finite and casting that representation back to REAL compares equal inside D1. Unsupported representations fail closed. This preserves the SQLite storage type and numerical round trip; it does not claim preservation of an underlying IEEE payload or physical database encoding. See [SQLite printf](https://www.sqlite.org/printf.html).

The SQL first selects at most 64 indexed rowids and raw byte lengths, then applies a cumulative 512 KiB raw-byte/cell-overhead budget before joining selected rows and materializing hex/JSON. Each row has a 256 KiB raw-byte/cell-overhead bound. An oversized first row returns a small sentinel and fails capture instead of skipping/truncating it. Large candidate payloads are not copied into the candidate CTE. Encoded pages are additionally capped at 1.1 MB. D1's own maximum row/blob limit does not substitute for these smaller explicit bounds. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/)

The complete encoded capture is capped at 16 MiB and 512 nonempty pages—up to 32,768 small rows, fewer when the byte limits bind. The page-count limit bounds the encrypted descriptor list within the existing 256 KiB checkpoint codec; it is not represented as unlimited history capacity. Oversized installations remain unsupported and return unknown without a candidate. Raising these limits needs a paged manifest design and a separately reviewed resource budget.

## Durable composition

`createSnapshotCapture({ pins, database, store, withClosedEpoch })` accepts the fixed installation/application-D1/updater-D1 pins, a trusted application binding and the existing encrypted updater artifact store. Application and updater D1 IDs must differ. Bootstrap must verify the actual binding identity. Replica-capable bindings require `withSession('first-primary')`; the fallback adapter must be primary-only.

`advance(operationUuid)` requires trusted authority for that installation, operation, job, positive closed epoch and exact schema-49 digest ledger. `withClosedEpoch` must retain closure and exclude writes/migrations for the entire multi-invocation capture—not just read a closed-state flag. Durable authority composition is still required before deployment. No application API, cookie, public caller or mutable schema/URL input supplies that authority.

The encrypted operation freezes identity, catalog, table position, decimal row cursor, total bytes and page descriptors. A page digest and length are recorded before chunk writes. Each advance writes at most eight encrypted chunks. Later advances seal complete stored chunks by authenticated readback, then compare-and-swap the cursor; lost chunk/seal/cursor acknowledgments remain resumable without skipping rows. A partially stored page is reread under the same fence and must match the saved digest. Final schema/ledger revalidation precedes the candidate's manifest digest.

`readPage(operationUuid, index)` is server-only: it requires completed capture plus matching constructor pins/catalog identity, and verifies sealed page bytes/digest. It exposes actual snapshot content and must never become an ordinary public status endpoint. Public candidate status contains only operation ID, schema/catalog/chain digests, page count, total length, manifest digest and `verified: false`. Original sensitive values remain encrypted in updater storage; no logging is performed.

## Local verification and remaining gates

Run `node --test tests/updater-snapshot-intermediate.test.mjs` for WU195. Actual local Miniflare D1 databases apply the trusted migrations through 47 and 48, then capture and replay populated documentation artifact histories, claim revision pins and operational upload/copy custody. Exact retained rows and foreign keys are checked after isolated replay. A mismatched catalog and unexpected source DDL reject. Captures retain `verified: false`; isolated replay validation does not establish safe application restoration. Existing shared snapshot/replay tests cover lost acknowledgments and tampering.

Run `node --test tests/updater-snapshot.test.mjs` with existing dependencies. Actual local Miniflare D1 tests cover int64 extrema, negative/min/max rowids, binary/NUL text/NULL/REAL projection, 64/64/2 small-row pagination, cumulative byte limits, raw oversize sentinel, populated operational tables omitted from logical backup 28, full schema-49 capture, encrypted retained pages after lost acknowledgment, changed epoch and unknown schema. The full capture test counts source and updater-store statements and requires each advance to remain within 50; injected authority work still needs its own reserved budget.

No hosted database is read, no credentials are loaded, and no bindings or cloud resources are created. Actual application restoration, positive deployed writer-fence evidence, external-provider preservation/reconciliation and operational retention remain separate gates. Validated isolated replay and durable maintenance composition have subsequent local evidence recorded in docs/PLANS/modular-p6-execution.md; their hosted acceptance remains outstanding. Exact before/after schema alone does not establish write quiescence.
