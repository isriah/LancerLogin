# LancerLogin v0.10.3 - Verified kiosk updates and a simpler private upgrade dispatch

## Highlights

- Admins can queue a connected physical kiosk to install **Latest stable** from **Kiosks** or **Settings → Updates**.
- The Pi update route is constrained to one argument-free root systemd unit. It resolves only the official `isriah/LancerLogin` `v0.n.n` latest release, verifies the installer SHA-256, and the installer verifies the architecture-specific kiosk archive SHA-256 before restarting the kiosk service.
- The private deployment workflow no longer asks for a duplicated typed confirmation. It retains the explicit operation choice, installation-slug validation, private-repository gate, resource checks, and GitHub's final **Run workflow** action.

## Upgrade notes

1. From **Settings → Updates**, download an **Entire installation** backup and open the private deployment workflow.
2. Select **Upgrade**, keep **Latest stable**, enter the existing installation slug, review the GitHub workflow details, and press **Run workflow**.
3. Install the matching `v0.10.3` Pi guided installer once on each kiosk that should receive managed updates. This release provisions the constrained updater. After that, use **Update to latest stable** in the dashboard whenever the kiosk is online.

The managed kiosk update path does not expose a remote shell or accept a custom URL, release tag, command, or argument.
