# LancerLogin v0.10.5 - Meeting, attendance, and kiosk polish

## Improvements

- Meetings now show separate Date, Start, and End columns. A single Delete action opens a clear confirmation: recurring occurrences can remove only the selected meeting or that meeting and future occurrences. Deleted meetings have an immediate Undo action that restores the same soft-deleted records.
- Discord calendar sync now continues after an individual failure. The Sync all control reports updated, skipped, and action-needed meetings beside the control; past meetings and over-limit Discord title or description values have specific reasons. Existing mapped events are still updated rather than duplicated.
- Attendance meeting choices use date followed by title, without the time. The absence-notice action follows the organization theme, attendance status badges align consistently, and unavailable corrections remain visible but muted. Discord roster linking and individual email commands have been removed from attendance rows.
- The kiosk refreshes Wi-Fi with a device-specific NetworkManager rescan before listing networks, keeps the slot control and numeric keypad inside the 800x480 maintenance layout, shows Wi-Fi bars or an Ethernet connector, and replaces the footer clock with kiosk-service uptime.
- The documentation workflow uses `actions/configure-pages@v6`, removing the known Node 20 action warning.

## Upgrade notes

1. Download an **Entire installation** backup from **Settings → Updates**.
2. In the private deployment repository, run **Install or upgrade LancerLogin** with **Upgrade**, **Latest stable**, and the existing installation slug.
3. When the dashboard reports `0.10.5`, an online compatible kiosk can install the matching latest-stable kiosk runtime from **Kiosks** or **Settings → Updates**. The first updater-capable Pi installation still requires the guided installer from `0.10.3` or later.

## Verification

- Confirm a one-time delete and a recurring-series delete both offer Undo before the next meeting action.
- Use **Sync all to Discord** with a mix of upcoming and past meetings; verify the result list explains any skipped or failed item.
- On the Pi, open network settings and confirm nearby Wi-Fi networks appear after refresh. Test the footer uptime and both Wi-Fi and Ethernet status symbols where available.
- Verify fingerprint maintenance slot selection and the numeric keypad at 800x480; no biometric templates or Wi-Fi passwords are exported or stored by this release.

## Known limits

- Pi/network behavior requires physical acceptance on the target hardware and NetworkManager environment. This release does not change stored network profiles, pairing, local PINs, mappings, or R503 templates.
- Discord's own scheduled-event limits still apply. LancerLogin now reports the affected meeting and continues with the rest of a bulk run.
