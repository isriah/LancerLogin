# LancerLogin v0.12.8 - Attendance reporting and dashboard operations refinement

## Changed

- Attendance actions now accept an optional note, show a temporary result beside the affected member, and omit obsolete contest, kiosk-ID, and passive-current-status panels.
- Reports is now an operational workspace with sortable attendance rates, a completed-meeting team trend, active/all-roster history, saved report views, and direct attendance-contest review.
- Administrators can set an explicit attendance reporting baseline in **Settings → Configuration**. Reports defaults to completed meetings on or after that date, clearly identifies the operational scope, and can still show all preserved history.
- Dashboard cards use consistent vertical spacing, Reports keeps contests directly beneath the trend, and desktop roster actions remain side by side.

## Upgrade impact

- The dashboard deployment applies migration `0015_attendance_reporting_baseline.sql`, which adds an optional organization setting and a reporting-period index. Existing attendance data is preserved.
- After upgrading, an Admin should set **Attendance reporting baseline** to the first meeting of the current reporting period. Based on the current reported meeting set, use `2026-08-26` if that is the intended first operational meeting.
- No Pi installer or kiosk software change is required.

## Verification

- D1 migration verification passed across the complete chain.
- API, dashboard, and Chromium desktop/mobile/kiosk smoke tests passed.
- This release has not deployed to an adopter installation or physical kiosk.
