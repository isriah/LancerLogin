# LancerLogin v0.13.0 - Roster, scheduling, and kiosk operations

## Changed

- Roster search now matches member name, email address, and member ID, with **Active members** and **All members** scopes.
- Each member has a stable detail page with attendance history and links from roster and reporting surfaces.
- Settings separates configuration, access management, and kiosk updates so operational controls appear where administrators expect them.
- Operators can save reusable meeting templates and start a new editable meeting from a template or an existing meeting.
- Kiosks now report a privacy-safe diagnostic snapshot: software version, uptime, reader state, network type and signal, last Wi-Fi scan, pending queue count, and recovery guidance. Credentials, raw scans, biometric data, and unrestricted logs remain excluded.
- The browser kiosk emulator uses the shared physical-kiosk presentation contract, labels simulated browser input, and records simulator-origin attendance separately from physical-kiosk activity.

## Upgrade impact

- Migrations `0016_kiosk_diagnostics.sql`, `0017_meeting_templates.sql`, and `0018_simulator_attendance_origin.sql` apply in sequence. They preserve existing kiosk, meeting, roster, and attendance records.
- Existing attendance rows are retained and labeled with their prior source; new browser-emulator attendance is explicitly recorded as simulator-origin activity.
- The release package includes the shared kiosk presentation module required by the physical kiosk runtime. Installing this public release does not automatically update any Pi.

## Before upgrading

1. Download an **Entire installation** backup from **Settings → Updates**.
2. In the private deployment repository, manually run **Install or upgrade LancerLogin**, choose **Upgrade**, keep **Latest stable** selected, enter the installation slug, and supply the required confirmation.
3. If updating a physical kiosk afterward, follow the normal installer/update procedure during a maintenance window. The dashboard upgrade does not remotely replace Pi files.

## Manual verification after upgrade

1. Search Roster by a member name, email, and member ID, then switch between active-only and all-members scopes.
2. Open a member detail page from Roster or Reports and confirm the attendance history is correct.
3. In Settings, confirm Configuration, Access, and Updates display the intended administrator controls.
4. Create a meeting from a template or duplicate an existing meeting, then verify its timing and recurrence remain editable.
5. On Kiosks, review a diagnostic snapshot and confirm it contains no credential, biometric, raw-scan, or unrestricted-log data.
6. At 800 by 480, open the browser emulator and confirm its simulated boundary is clearly labeled and it does not appear as the physical kiosk.

## Known limits

- The browser emulator is a foundation only; protected maintenance, enrollment/mapping, networking, and recovery/update flows remain follow-on work.
- This release has not deployed to an adopter installation or received physical Raspberry Pi/R503 acceptance. Those checks remain separate from local and browser verification.
