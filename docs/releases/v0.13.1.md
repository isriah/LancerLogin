# LancerLogin v0.13.1 - Dashboard and kiosk reliability refinement

## Included work units

- WU-011 — Reports meeting-type correctness
- WU-012 — Member participation start dates
- WU-013 — Future-meeting attendance semantics
- WU-014 — Calendar-led attendance navigation
- WU-015 — Dashboard visual stability
- WU-016 — Dashboard card alignment refinement
- WU-017 — Kiosk status-card presentation
- WU-018 — Kiosk Wi-Fi scan authorization repair

## Changed

- Reports now correctly distinguishes All, Regular, and Optional meetings, excludes test meetings, and keeps member and filter controls responsive.
- Each roster member has an editable participation-start date. Attendance obligations, absence states, and reporting omit meetings before that date while preserving historical records.
- Future meetings use a neutral attendance state and do not trigger absence notifications before they start.
- Attendance includes calendar-led navigation to the relevant Meetings or Attendance workspace.
- Dashboard loading uses an accessible overlay without moving page layout; themed backgrounds remain stable between routes. Data controls, shared card headers, roster actions, and Setup completion controls have improved alignment.
- The Kiosks page presents a centered Healthy status pill when diagnostics are healthy, retains the diagnostic data and fixed recovery actions, and removes the obsolete recovery-guidance copy.
- After local settings-PIN authorization, a supported kiosk can rescan Wi-Fi through the narrow NetworkManager authorization path without exposing saved network credentials or arbitrary command access.

## Upgrade impact

- Migration `0019_member_participation_start_dates.sql` assigns existing members an attendance-required-from date from their recorded creation date and adds an installation/date index. It preserves all meeting and attendance history.
- No new dashboard or cloud configuration is required.
- The kiosk authorization repair is included in the public release package. Installing this release does not automatically update a Raspberry Pi.

## Before upgrading

1. Download an **Entire installation** backup from **Settings → Updates**.
2. In the private deployment repository, manually run **Install or upgrade LancerLogin**, choose **Upgrade**, keep **Latest stable** selected, enter the installation slug, and supply the required confirmation.
3. Schedule any physical-kiosk update separately and follow the normal installer/update procedure during a maintenance window.

## Manual verification after upgrade

1. In Roster, confirm a member’s participation-start date can be viewed and changed; verify Reports omits meetings before that date for that member.
2. In Reports, switch among All, Regular, and Optional meeting filters and confirm test meetings remain absent.
3. From Attendance, select future and current/past calendar meetings and confirm the correct destination workspace opens.
4. Navigate between dashboard pages on desktop and mobile widths; confirm loading does not shift content and card controls remain legible.
5. On Kiosks, confirm the Healthy pill appears only for a healthy kiosk while diagnostics and authorized actions remain available.
6. On a supported physical Pi, after local settings-PIN authorization, rescan Wi-Fi and confirm NetworkManager does not return the prior authorization error. Confirm locked-out or unauthorized requests remain denied.

## Known limits

- Automated verification uses mocked providers, local D1, and simulated kiosk transport. This release has not deployed to an adopter installation.
- Supported-Pi validation of the Wi-Fi rescan repair remains required; dashboard publication does not update any Pi automatically.
