# LancerLogin v0.14.0 - Operations, scheduling, and Discord workflow refinement

## Included work units

- WU-019 through WU-032

## Changed

- Contest resolutions provide required-reason and failure feedback. Pending contests are surfaced from the dashboard shell while Reports remains focused on attendance reporting.
- Meetings, Attendance, Roster, Settings, Updates, Data management, and guided setup have focused usability, accessibility, layout, and copy improvements.
- Meeting templates are no longer available in normal scheduling workflows; stored template records and existing meetings are preserved.
- Discord calendar synchronization now reports permission failures clearly and respects provider rate-limit retry guidance.
- Reports restores correct All, Regular, and Optional completed-meeting filtering and keeps leaderboard controls responsive.
- Members can safely self-pair Discord with `/pair <member-id>` after verified Discord setup. The signed command rejects invalid, inactive, and already-paired records; Roster conditionally displays paired Discord IDs.

## Upgrade impact

- Migration `0020_discord_member_pairing.sql` adds an installation-scoped uniqueness constraint for non-empty Discord user IDs. Existing roster and attendance data are preserved.
- No new secrets, deployment credentials, or Pi changes are required. Existing Discord integrations must remain verified for self-pairing and the conditional Roster column.

## Before upgrading

1. Download an **Entire installation** backup from **Settings → Updates**.
2. Run the guarded private-repository upgrade workflow using **Latest stable** and the required confirmation.
3. Schedule any physical kiosk update separately during a maintenance window.

## Manual verification after upgrade

1. Confirm Meetings and Reports filters work at desktop and mobile widths.
2. Confirm pending contest notification leads operators to the review workflow.
3. With verified Discord configured, run `/pair <member-id>` for an unlinked active member, then confirm the conditional Discord ID column in Roster. Confirm duplicate, inactive, and already-linked attempts are rejected.
4. Confirm Data-management confirmations and Settings navigation retain their existing authorization boundaries.

## Known limits

- Automated verification uses local D1, mocked providers, and simulated kiosk transport. This release does not deploy an adopter installation or update a Raspberry Pi.
