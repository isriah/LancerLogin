# LancerLogin v0.16.0 - Dashboard meeting browser and update reliability

## Included work units

- WU-045 and WU-050

## Changed

- Dashboard is now the single meeting browser. Its remembered Calendar and Table views share a meeting selector and Add meeting action, calendar ranges can move backward and forward, and selecting a meeting opens its canonical `/meetings/[ID]` workspace.
- Meetings and Attendance are no longer separate primary-navigation destinations. Existing `/meetings` bookmarks open Dashboard's searchable Table view, while the v0.15.0 Attendance compatibility redirects remain available.
- The Updates page now displays locally available installation and kiosk information without waiting for GitHub's public release feed. Public release checks time out after four seconds, show a clear degraded state, retry automatically, and cannot overlap.
- The update notification uses the same bounded release lookup, while the existing backup-first dashboard update handoff and guarded kiosk updater remain unchanged.

## Upgrade impact

- No database migrations, new secrets, dependency changes, deployment configuration changes, or Raspberry Pi service changes are included.
- Existing Dashboard access and Admin/Operator permissions are unchanged.
- Bookmarks to `/meetings` now resolve to `/dashboard?view=table`; direct `/meetings/[ID]` links continue to open meeting detail.

## Before upgrading

1. Download an **Entire installation** backup from **Settings → Updates**.
2. Run the guarded private-repository upgrade workflow using **Latest stable** and the required confirmation.
3. No physical kiosk update is required for this dashboard-only release.

## Manual verification after upgrade

1. Open Dashboard, switch between Calendar and Table, reload the page, and confirm the selected view is remembered.
2. Move the calendar backward and forward, then open meetings from a calendar event, table row, and meeting selector; confirm each reaches the expected `/meetings/[ID]` page.
3. Open an existing `/meetings` bookmark and confirm it reaches Dashboard's searchable Table view without disrupting browser Back/Forward behavior.
4. Open **Settings → Updates** with the public GitHub release feed available and unavailable; confirm installed dashboard and kiosk information remains usable and the latest-release state recovers automatically.
5. Confirm the update action still downloads an entire-installation backup before opening the private GitHub workflow.

## Known limits

- Automated verification uses local fixtures, mocked external responses, and simulated kiosk transport. This release does not deploy an adopter installation or update a Raspberry Pi.
- In-place meeting creation, meeting-detail management dialogs, meeting-local Discord and contest operations, and displaced meeting-utility cleanup remain planned follow-on work in WU-046 through WU-049.
