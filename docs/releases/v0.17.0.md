# LancerLogin v0.17.0 - Dashboard meeting creation and kiosk version visibility

## Included work units

- WU-046 and WU-051

## Changed

- Meetings can now be created without leaving Dashboard. The accessible dialog supports one-time meetings, recurring series, and duplication from an existing meeting while preserving the active Calendar or Table view.
- Successful creation refreshes the active meeting browser and selector, announces the created count, and keeps the current route. Validation and API errors remain in the dialog and reliably receive keyboard focus.
- The physical kiosk footer now shows its running LancerLogin release while the fingerprint reader is online. Development or missing-version environments use a safe fallback, and reader failures continue to replace the version with the existing offline warning.

## Upgrade impact

- No database migrations, new secrets, dependency changes, or deployment-configuration changes are included.
- Existing Dashboard permissions, meeting scheduling rules, Discord best-effort synchronization, kiosk pairing, queue state, and reader behavior are unchanged.
- The private dashboard installation and physical kiosk must both be upgraded to receive the complete release. The kiosk upgrade preserves pairing, branding, queued scans, fingerprint slot mappings, and the local settings PIN.

## Before upgrading

1. Download an **Entire installation** backup from **Settings → Updates**.
2. Run the guarded private-repository upgrade workflow using **Latest stable** and the required confirmation.
3. After the dashboard upgrade completes, update the physical kiosk to **Latest stable** from **Kiosks** or **Settings → Updates**. If remote kiosk updates have not yet been enabled on that Pi, use the version-matched guided installer instead.

## Manual verification after upgrade

1. Open Dashboard in Calendar view, create a one-time meeting, and confirm the dialog closes, the created count is announced, the calendar and meeting selector refresh, and the route does not change.
2. Repeat from Table view with a duplicated recurring meeting, then submit an invalid or conflicting schedule and confirm the error remains visible in the dialog and receives keyboard focus.
3. On the physical kiosk, confirm the footer shows `LancerLogin v0.17.0` while the reader is online and still shows queue count and uptime.
4. Disconnect or stop the fingerprint reader and confirm the version is replaced by the existing reader-offline warning.

## Known limits

- Automated verification uses local fixtures, mocked external responses, and simulated kiosk transport. Physical Raspberry Pi and R503 acceptance remains a manual post-upgrade check.
- Meeting editing and deletion dialogs, meeting-local Discord and contest actions, and displaced meeting-utility cleanup remain planned follow-on work in WU-047 through WU-049.
