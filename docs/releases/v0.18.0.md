# LancerLogin v0.18.0 - Meeting operations and kiosk feedback

## Included work units

- WU-047, WU-048, WU-049, WU-052, and WU-053

## Changed

- Meeting detail now owns the actions that affect one meeting: edit, duplicate, delete, Discord calendar sync, Discord absence notification, attendance corrections, and meeting-scoped contest review. Recurring meetings retain occurrence-only and this-and-future choices, and a deletion returns to Dashboard with Undo.
- Dashboard Table remains the bulk workspace for meeting search, independent checkbox selection, bulk deletion, and Sync all to Discord. Dashboard no longer duplicates the live attendance roster or contest list; meeting detail and the global contest notifier remain the complete operational paths.
- Kiosks now places verified Discord kiosk-status synchronization beside physical kiosk health. The control is hidden unless Discord is enabled and verified, and existing Admin/Operator authorization remains enforced by the API.
- The physical kiosk gives clearer visual feedback without changing attendance outcomes: blue while processing, purple for a duplicate scan, green when a recognized offline scan is safely queued, red for offline unknown or rejected scans, and a pulsing connectivity indicator while offline. Reduced-motion users receive persistent non-animated cues.
- The repository now has a mandatory dashboard visual-language standard and shared semantic tokens for future dashboard work. Existing screens are not broadly restyled by this release.

## Upgrade impact

- No database migrations, new secrets, dependency changes, or deployment-configuration changes are included.
- Existing meetings, recurring-series records, attendance history, contest audit history, kiosk pairing, fingerprint slot mappings, queued scans, branding, and local settings PIN are preserved.
- The private dashboard installation and physical kiosk must both be upgraded to receive the complete release. Discord-powered controls continue to require an enabled and successfully verified Discord integration.

## Before upgrading

1. Download an **Entire installation** backup from **Settings → Updates**.
2. Run the guarded private-repository upgrade workflow using **Latest stable** and the required confirmation.
3. After the dashboard upgrade completes, update the physical kiosk to **Latest stable** from **Kiosks** or **Settings → Updates**. If remote kiosk updates have not yet been enabled on that Pi, use the version-matched guided installer instead.

## Manual verification after upgrade

1. Open a recurring meeting, edit only one occurrence, then edit that occurrence and all future meetings; confirm the chosen scope is respected.
2. Duplicate a meeting, delete one occurrence, confirm the return to Dashboard, and use Undo. In Dashboard Table, confirm row navigation remains independent from checkbox selection and bulk deletion.
3. With Discord enabled and verified, confirm meeting-detail calendar, absence, and contest actions follow their time and meeting scope; then confirm **Kiosks → Sync Discord status** updates the persistent health message. Disable or unverify Discord and confirm those controls are absent.
4. On the physical kiosk, exercise a normal scan, duplicate scan, recognized offline scan, and unknown or rejected offline scan. Confirm their blue, purple, green, and red cues, the offline connectivity pulse, and the persistent alternatives when reduced motion is enabled.

## Known limits

- Automated verification uses local fixtures, mocked external provider responses, and simulated kiosk transport. Physical Raspberry Pi/R503 behavior and live Discord delivery remain manual post-upgrade checks.
- The new dashboard visual-language standard is the contract for subsequent work; v0.18.0 does not claim that every existing dashboard surface has already been retrofitted to it.
