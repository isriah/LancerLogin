# LancerLogin v0.19.0 - Dashboard design conformance

## Included work units

- WU-054, WU-055, WU-056, WU-057, WU-058, WU-059, and WU-060

## Changed

- The complete React dashboard now follows one visual-language contract for typography, spacing, surfaces, controls, focus, semantic status colors, responsive layout, dark mode, and adopter branding.
- Sign-in, first-Admin setup, guided setup, the authenticated shell, navigation, loading states, popups, and unavailable-page recovery now share consistent hierarchy and accessible interaction behavior.
- Dashboard meeting browsing, meeting detail, attendance operations, Discord and contest states, and their create/edit/duplicate/delete dialogs now remain readable and operable across desktop and mobile layouts.
- Reports, Roster, member detail, imports, and member-management dialogs now use consistent cards, tables, filters, status treatment, focus containment, and contained data scrolling.
- Kiosks now distinguishes healthy, degraded, offline, and unpaired states consistently while preserving its diagnostic privacy, pairing rules, command allowlist, role checks, and the boundary around physical kiosk presentation.
- Every Settings category now uses the shared form and panel system, including integration states, validation feedback, telemetry choice, data backup/restore/delete dialogs, guided setup, and update comparisons.
- Durable browser coverage now audits all 14 governed routes at 1280x900 and 390x844 in light and dark modes with reference adopter colors, reduced motion, target sizing, labels, heading order, clipping, and page overflow checks.

## Upgrade impact

- No database migrations, new secrets, dependency changes, or deployment-configuration changes are included.
- Product policy, authorization, stored data, provider behavior, meeting and attendance outcomes, kiosk pairing, fingerprint data, and physical kiosk presentation are unchanged.
- Existing organization branding remains supported and is now exercised across the dashboard conformance matrix.

## Before upgrading

1. Download an **Entire installation** backup from **Settings → Updates**.
2. Run the guarded private-repository upgrade workflow using **Latest stable** and the required confirmation.
3. This dashboard-only release does not require a physical kiosk update.

## Manual verification after upgrade

1. Check sign-in and the authenticated dashboard at desktop and phone widths in light and dark modes; confirm the organization colors, navigation, focus rings, and status messages remain clear.
2. Open Dashboard, a meeting, Reports, Roster, a member, Kiosks, and every Settings category; confirm controls are reachable, content wraps without page-level horizontal scrolling, and tables scroll only inside their containers where necessary.
3. Exercise representative dialogs for meeting management, attendance correction, roster/member management, kiosk pairing, and data restore/delete; confirm keyboard focus stays inside and returns to the opener when closed.
4. Verify Admin-only controls remain absent for an Operator and that disabled, unconfigured, degraded, success, and error states remain explicit without relying on color alone.

## Known limits

- Automated verification uses local fixtures and mocked external provider responses. Live Google, Resend, Discord, Cloudflare, Raspberry Pi, and R503 behavior remains outside this dashboard presentation release.
- Physical kiosk presentation, the kiosk simulator display, provisioning pages, and public documentation styling are intentionally outside the governed dashboard scope.
