# LancerLogin v0.21.0 - One-way Google Calendar meeting sync

## Included work units

- WU-074

## Changed

- Admins can configure Google Calendar independently from Google sign-in, authorize one Google account, and select one calendar where that account can write events.
- New LancerLogin meeting occurrences can create one mapped Google event with the generic name **LancerLogin meeting** and the meeting's start and end times.
- Editing one occurrence or future occurrences updates only the matching mapped event times. Hiding a meeting deletes its mapped event, while restoring the meeting creates a new event identity.
- Meeting changes remain saved when Google is unavailable. Failed Calendar work stays in a durable queue, retries every five minutes, and can be retried manually from **Settings -> Integrations**.
- Calendar status appears after meeting create, edit, hide, and restore actions, while the integration card shows the selected calendar and any waiting or failed deliveries.

## Required live Google Calendar release check

Before publishing the release tag, use a supported Google Calendar account to verify authorization, calendar selection, meeting create, edit, hide, restore, and retry recovery. Confirm each action changes only the intended generic Calendar event and that a provider failure never prevents the LancerLogin meeting change from being saved.

## Upgrade impact

- D1 migration `0026_google_calendar_sync.sql` adds the optional Calendar enablement flag, separately encrypted authorization storage, meeting-to-event mappings, and the durable operation queue.
- Google Calendar remains off until an Admin explicitly configures and authorizes it. Existing meetings are not backfilled.
- Calendar authorization is separate from Google sign-in and does not change sign-in enablement or sole-Admin lockout protection.
- The OAuth client must allow the installation-specific Calendar callback shown in **Settings -> Integrations**. Authorization requests only Calendar-list read access and Calendar-event write access.
- No dependency changes, Pi service changes, or kiosk installation are required.

## Before upgrading

1. Download an **Entire installation** backup from **Settings -> Updates**.
2. If Google Calendar sync will be enabled, prepare a Google OAuth web client whose authorized redirect URI exactly matches the Calendar callback shown by the installation.
3. Run the guarded private-repository upgrade workflow using **Latest stable** and the required confirmation.
4. A physical kiosk update is not required for this release.

## Manual verification after upgrade

1. Open **Settings -> Integrations**, enable Google Calendar, save its OAuth client, and confirm the displayed callback exactly matches the authorized redirect URI in Google.
2. Authorize the intended Google account and select a calendar where it has writer or owner access.
3. Create a test meeting. Confirm one Google event appears with the name **LancerLogin meeting**, the correct start and end times, and no meeting title, notes, roster, attendance, organization name, attendees, reminders, or description.
4. Edit the test meeting time and confirm the same mapped event changes without creating a duplicate.
5. Hide the test meeting and confirm its event is removed. Restore the meeting and confirm one new mapped event is created.
6. Cause or simulate a temporary provider failure, confirm the meeting change still saves and appears as waiting or failed, then use **Retry now** and confirm the operation completes without a duplicate event.
7. Disable Calendar sync and confirm queued delivery pauses. Re-enable it and confirm delivery can resume.

## Known limits

- Calendar sync is one-way. Google-side edits never change LancerLogin.
- Only one destination calendar is supported. Existing meetings are not backfilled.
- LancerLogin sends only a deterministic opaque event identity, the fixed generic event name, and start/end timestamps. It does not send attendees, reminders, descriptions, meeting titles, notes, roster, attendance, or organization data.
- Removing the Calendar connection clears local authorization and mappings but does not promise to remove events already delivered to Google.
- Automated verification uses local D1 and provider fakes. The supported-calendar check above must pass before the release tag is published.
- This release does not deploy or upgrade any private adopter installation and does not update a Raspberry Pi.
- The repository's configured visual browser is Chromium; Firefox and WebKit were not run separately.
