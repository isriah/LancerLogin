# LancerLogin v0.22.1 - Bounded Discord calendar backfills

## Included work units

- WU-080

## Changed

- Discord **Sync all meetings** now advances through separate ten-meeting Worker requests instead of attempting the entire active meeting set in one invocation.
- Scheduled Discord calendar recovery also processes at most ten operations per Worker invocation, leaving remaining work durably queued for later passes.
- A permission or rate-limit failure that leaves work queued stops the current browser backfill before it requests later pages. The dashboard keeps the completed, queued, skipped, and failed totals visible for recovery.
- Continuation cursors are validated before any provider request, and the existing 100-meeting dashboard action ceiling remains in place.

## Upgrade impact

- No D1 migration, dependency, environment-secret, or Discord permission change is included.
- Existing Discord credentials, verification state, event mappings, durable operations, and provider event IDs are preserved.
- The Dashboard and Worker must both be upgraded because the fix pairs a paged API response with client-side continuation.

## Required post-release live check

The guarded private upgrade installs published stable tags, so supported-server validation follows publication:

1. Upgrade the private Dashboard installation to v0.22.1 after taking an **Entire installation** backup.
2. Open **Settings -> Integrations -> Discord bot** and run **Sync all meetings** with the current 48-meeting test set.
3. Confirm the action completes without `Too many subrequests by single Worker invocation`, reports all active meetings checked, and leaves no subrequest-limit failures.
4. Confirm the existing `v0.22.0 Provider Validation` scheduled event remains exactly once at 7:15-8:15 PM and that rerunning the action does not create a duplicate.
5. If Discord returns a genuine permission or rate-limit failure, confirm later batches stop, the remaining work stays queued, and a later recovered run completes without duplicates.

## Known limits

- Calendar sync remains one-way; provider-side edits never modify LancerLogin.
- The action checks at most 100 active meetings. Larger histories require a later product decision rather than silently expanding one administrative action.
- Automated verification uses provider fakes and cannot prove a live Discord server's current permission or rate-limit state.
- The physical kiosk was offline and unresolved on the local network during v0.22.0 validation. This patch does not alter kiosk software or connectivity, and no Pi update is included.
