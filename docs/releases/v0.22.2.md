# LancerLogin v0.22.2 - Discord command repair for upgraded integrations

## Included work units

- WU-081

## Changed

- An already-configured Discord integration now exposes **Reconcile Discord commands** in **Settings -> Integrations** so an Admin can create or update the server's `/pair` and `/attendance-report` commands without replacing credentials or repeating verification.
- Discord configurations saved before the Application ID field was introduced can obtain the bot application's authoritative ID from Discord during reconciliation. A conflicting saved Application ID is still rejected.
- Reconciliation is repeat-safe and preserves verification, encrypted credentials, calendar mappings and queued operations, channel-manager and anomaly-report settings, and member pairings when it succeeds or fails.

## Upgrade impact

- No D1 migration, dependency, environment-secret, Discord permission, or configuration-schema change is included.
- Existing Discord configuration and operational state are preserved.
- The Dashboard and Worker must both be upgraded because the repair pairs a new administrative action with its protected API endpoint.

## Required post-release live check

The guarded private upgrade installs published stable tags, so supported-server validation follows publication:

1. Take an **Entire installation** backup, then upgrade the private Dashboard installation to v0.22.2.
2. Open **Settings -> Integrations -> Discord bot** and select **Reconcile Discord commands** without replacing the saved credentials.
3. Confirm the action succeeds and the configured server exposes exactly the current guild-scoped `/pair` and `/attendance-report` commands.
4. Run the reconciliation action again and confirm it succeeds without creating duplicate commands.
5. Confirm Discord remains verified and its calendar delivery, channel-manager, anomaly-report, and member-pairing state remains unchanged.
6. Exercise `/pair` and `/attendance-report` in the configured server and confirm their existing signed, private behavior remains intact.

## Known limits

- The managed commands remain guild-scoped; they are not registered globally and are unavailable in direct messages or other servers.
- Reconciliation requires the saved bot token to remain valid and the bot to remain installed in the configured server with the documented permissions.
- Automated verification uses provider fakes and cannot prove the live server's current command state or permissions.
- No private installation deployment, Discord provider mutation, or Pi update is part of the public release workflow.
