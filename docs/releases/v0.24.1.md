# LancerLogin v0.24.1 - Worker-compatible web update bridge

## Release scope

Web update runtime repair: web updates use Cloudflare Workers-supported manual requests and reject unexpected redirects without forwarding credentials. The published v0.24.0 and v1.0.0 updater used an unsupported redirect mode and failed before preparing an update. Their immutable releases remain preserved.

Actual Worker-runtime regressions cover preparation, pinned dispatch/status, authenticated/public redirects, no credential forwarding and durable ambiguous-dispatch replay. Polling cadence is unchanged.

## Migration and configuration impact

- No new D1 migrations, dependencies, permissions or secrets. Retain the existing 29-migration prefix and installation identities, URLs, encryption/session credentials, pairing and attendance.
- Existing v0.24.0 web installations require the official corrected v0.24.1 manual web bridge through their reviewed private provisioning workflow, then an actual in-app V1.0.1 update. Prepare its pinned release, save the associated Entire installation backup, confirm saved and start once. Track the same durable request through independent API/Pages health before reloading.
- The already bridged v0.24.0 Pi helper supports V1.0.1. Physical updates remain separate; verify actual installed version, fixed no-argument service, helper ownership and retained mappings/PIN. A Pi that missed the original helper bridge still requires the checksum-verified exact-v0.24.0 bootstrap described in [KIOSK.md](../KIOSK.md).
- Builds/checkpoints precede mutation. Keep secure web/Pi backups, D1 recovery bookmarks and code predecessors. Never automatically restore D1 or an old pending queue, rotate credentials or recreate resources.

## Verification and acceptance limits

Native Windows/Linux Worker tests passed for the integrated repair with synthetic provider IO. Exact exported release, browser, dependency-audit and Linux artifact gates are required before publication; publication alone proves no live upgrade. Actual isolated in-app dispatch/tracking and existing web/Pi acceptance remain separately gated.

The operator waived additional v0.24.0 bridge scanning, controlled queue replay, enrollment and reboot tests. These are not claimed passed. Earlier installed-helper/reader/touch/PIN/mapping confirmations do not establish untested replay behavior. See [WEB-UPDATES.md](../WEB-UPDATES.md) for deliberate recovery and maintenance handling.
