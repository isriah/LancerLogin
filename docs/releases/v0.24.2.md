# LancerLogin v0.24.2 - Reliable web update bridge

## Release scope

Fixes authenticated update starts that stopped after recording their audit: the atomic claim now identifies its winning row independently of trigger-inclusive change counts. Concurrent starts still dispatch only once and retain their audit history.

Fixes the private executor's Pages deployment command. Worker deployment keeps its generated configuration; Pages receives only supported arguments. The earlier Worker redirect compatibility repair is retained. Polling cadence is unchanged.

## Migration and configuration impact

- No new migrations, dependencies, permissions or secrets. Preserve all 29 migrations, installation identities, pairing, attendance and encryption/session keys.
- Existing web installations require the corrected private controller and manual official v0.24.2 bridge. Then use Settings > Updates to prepare v1.0.2, download its associated Entire installation backup, confirm it is saved, and start once.
- The Pi already bridged to v0.24.0 can update separately to v1.0.2 using its fixed helper. See [KIOSK.md](../KIOSK.md) if the helper bridge was missed.
- Keep completed and failed request history. A recovery-required installation needs deliberate schema-compatible deployment recovery before another request. Never automatically restore D1 or an older pending kiosk queue. See [WEB-UPDATES.md](../WEB-UPDATES.md).

## Verification and acceptance limits

The repairs passed native Worker audit/concurrency regressions, actual locked Wrangler argument validation and recovery scenarios. An isolated authenticated app update completed all build, checkpoint, migration, API, Pages and health stages using the repaired controller and dispatch candidate. Data counts, all 29 migrations and the signed-in session were retained; maintenance cleared and the dashboard explicitly reloaded. A real partial-deployment failure was recovered through a reviewed code-only rollback and guarded completed-run recovery without restoring D1.

That rehearsal used a candidate on v0.24.1 with official v1.0.1 as its target. Exact exported release, browser, strict dependency-audit and Linux archive gates remain required for this version. Publication does not establish existing-installation or physical Pi acceptance. Earlier waived physical scan, queue replay, enrollment and reboot checks remain unclaimed.
