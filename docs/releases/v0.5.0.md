# LancerLogin v0.5.0 — Attendance lifecycle and operations home

This release turns attendance into a complete arrival/departure workflow and reshapes the dashboard around day-to-day operations. It is designed as an in-place upgrade for adopter-owned LancerLogin v0.4 installations; it does not connect to or migrate any pre-LancerLogin attendance system.

## What changed

- Every meeting now requires an end time. A member scans on arrival and again on departure. One arrival scan is shown as **Active · not checked out**; a completed pair is **Present**. After scanning closes, an incomplete or missing pair is **Absent** unless a reasoned correction or excuse overrides it.
- Scanning closes at the scheduled end plus one organization-wide allowance under **Settings → Organization**. The default is 30 minutes, and meetings cannot override it.
- Home now starts with a rolling five-week calendar: last week, the current week, and the next three weeks. It also shows live rosters for meetings in progress and outstanding Discord contests.
- **Kiosks** is a top-level page with physical kiosk heartbeat, reader, release, and pairing details plus the separate browser simulator entry point.
- Guided setup temporarily takes over the Admin workspace until complete, then disappears from primary navigation. It remains available from Organization settings and Kiosks. Completion still uses the accessible celebration and returns to Home.
- Organization primary and secondary colors now apply in light, dark, and follow-device appearances. Buttons calculate readable foreground text. Transparent logos are display-cropped and receive an automatic contrasting backing; the original D1 image remains unchanged and an Admin can override the backing.
- Discord absence notices are processed every five minutes after each meeting's scan cutoff. Delivery and eligible recipients are recorded durably. A contest opens only after Discord verifies the Ed25519 signature and confirms that the clicking user was mentioned, is still linked to that member, and is still absent. Review requires a note; approval adds an audited attendance correction without deleting scans.
- The browser simulator now exercises separate arrival and departure scans without needing to wait between them. The physical kiosk continues to infer the next action from the member's scan history and reports the accepted action on screen.
- The private deployment workflow defaults to the latest public release, supports an explicit tag choice, and uploads initial Worker secrets through the supported Wrangler bulk-secret path.

## Upgrade and data migration

Migration `0005_attendance_lifecycle.sql` adds the organization-wide scan allowance, logo backing preference, attendance action, and durable Discord notification/recipient fields. To preserve existing attendance credit, each pre-v0.5 member/meeting event set receives one synthetic legacy checkout at its latest recorded time. A legacy meeting with no end time receives an inferred end one hour after its start; review those meeting times after upgrading. Existing roster, meetings, corrections, users, integrations, kiosk pairing, and setup progress remain in place.

Dashboard backups created by v0.4 remain restorable after this upgrade. During restore, their branding defaults and attendance pairs are normalized to the v0.5 schema without changing the backup file itself.

Before upgrading, download an **Entire installation** backup from **Settings → Updates** or **Settings → Data**. In the private deployment repository, manually run **Install or upgrade LancerLogin**, choose **Upgrade**, keep **latest** selected (or choose **specific tag** and enter `v0.5.0`), enter the exact confirmation shown by the workflow, and review the resource names before authorizing the job.

## Configuration note for Discord

To use the new contest button, rotate the Discord configuration under **Settings → Integrations** and include the Discord application's 64-character hexadecimal public key. Copy the displayed Interactions Endpoint URL into the Discord Developer Portal. Discord remains optional and never blocks roster import, kiosk operation, or core attendance.

## Manual verification after upgrade

1. Confirm the old roster, meetings, users, and kiosk status are intact. Review the end time of any older meeting that previously had no end.
2. Open Organization settings, check the 30-minute late-scan value, and verify branding in light and dark mode.
3. Create a test meeting with start and end times. In the simulator, submit arrival then departure; confirm the row changes from Active to Present.
4. Confirm Home shows the meeting in the rolling calendar and shows live attendance during its scan window.
5. Open Kiosks and verify the physical/simulator status cards.
6. If Discord is enabled, test the integration after rotating its public key, then verify a post-cutoff notice and contest review in a non-production test meeting.

## Known boundaries

Single physical kiosk only. Fingerprint synchronization, multi-kiosk support, PDF/Sheets export, automatic dashboard-triggered deployment, captive-portal automation, and migration from another attendance product remain out of scope. Physical Pi/R503 acceptance still requires adopter-owned test hardware.
