# LancerLogin v0.6.0 — Recurring meetings and dashboard refinement

This release makes recurring schedules and roster changes easier to manage, tightens the guided setup experience, and puts update and integration help where Admins need it. It upgrades an adopter-owned LancerLogin installation in place and does not connect to or migrate any pre-LancerLogin attendance system.

## What changed

- Meetings can repeat daily, weekly, every two weeks, or monthly between selected start and end dates. Generated meetings retain the organization's local wall time across daylight-saving changes.
- Meetings now appear in a searchable table containing title, date, start/end times, test status, recurrence, and series range. Admins and Operators can edit every meeting attribute and choose one occurrence or that occurrence and the future series.
- Attendance now focuses only on existing meetings. Meeting creation and scheduling stay on Meetings.
- Roster CSV imports first show an accessible preview table. Admins then explicitly choose to add/update rows or replace the active roster; replacing preserves attendance history and dashboard credentials while deactivating omitted members.
- Dashboard access is managed with roster members on Roster, while non-rostered Admin and Operator accounts remain supported.
- The guided setup reopens as a temporary, navigation-free workflow at its first step and returns to Home only when Finish is selected. Theme choice persists in the browser and defaults to dark for new browser profiles.
- Page headings, responsive containment, focus treatment, field-level errors, button sizing, and wrapping were made more consistent throughout the dashboard.
- Admins see a small dashboard notification only when a newer public release exists. Updates still require an installation backup and explicit authorization in the private GitHub deployment workflow; LancerLogin never updates itself.
- Google OAuth, Resend, and Discord settings now include beginner-oriented setup steps, exact callback values, official console links, permissions guidance, testing, and secret-rotation reminders beside their configuration forms.

## Data migration

Migration `0006_recurring_meetings.sql` adds optional series identifier, recurrence frequency, series start date, and series end date fields to meetings. Existing meetings remain one-time meetings. Existing roster, attendance, credentials, integrations, kiosk pairing, branding, and setup state remain unchanged.

Meeting backups now use schema version 3 and include recurrence metadata. Backups from earlier LancerLogin releases remain restorable and are normalized as one-time meetings.

## Upgrade

Before upgrading, download an **Entire installation** backup from **Settings → Updates** or **Settings → Data**. In the private deployment repository, manually run **Install or upgrade LancerLogin**, choose **Upgrade**, keep **latest** selected (or choose **specific tag** and enter `v0.6.0`), enter the existing installation slug, and type the required confirmation.

The dashboard may notify you that this release is available and can open the correct private workflow after downloading a backup. It cannot dispatch that workflow or access a Cloudflare token.

## Suggested acceptance check

1. Confirm the dashboard opens in dark mode in a browser that has no saved preference, then switch themes and refresh.
2. Create a weekly series that crosses a daylight-saving boundary and confirm every occurrence retains the selected local start and end time.
3. Search the meeting table by title, date, time, test status, and recurrence; edit one occurrence and then a future series.
4. Preview a roster CSV, test both merge and replace summaries, and confirm no roster change happens until the final import button is selected.
5. Reopen guided setup, verify the dashboard navigation is hidden, and select Finish to return Home.
6. Review all three integration guides without saving credentials, then test only the integrations configured for this installation.
7. Confirm the update notice points to **Settings → Updates** and that no deployment starts until the private GitHub workflow is manually authorized.

## Known limits and future work

- Recurrence supports daily, weekly, biweekly, and monthly patterns, not arbitrary weekday rules or exceptions.
- The existing setup simulator still supports hardware-free test attendance. A full kiosk-screen simulator with a roster fingerprint-event dropdown and expanded attendance testing remains planned for a future release; it was intentionally deferred from v0.6.0.
- Multi-kiosk operation, biometric synchronization, captive-portal automation, PDF/Sheets export, and migration from another attendance installation remain out of scope.
- Physical Raspberry Pi, display, and R503 acceptance still requires adopter hardware.
