# v1.0.3 - Community telemetry retirement

Community telemetry has been removed. The first-Admin form no longer asks for usage-reporting consent, and Settings no longer contains a telemetry-only Privacy page. Existing privacy links redirect to Data.

Older bootstrap consent input is accepted and ignored. Authenticated Admin privacy GET/PATCH responses always report telemetry disabled, without writing consent or sending reports. Historical consent flags cannot reactivate reporting, including scheduled execution and error paths. Applied migrations and historical backup fields remain unchanged and inert. Attendance and integration schedules remain supported.

The maintainer collector, provisioning workflow and workspace dependency are retired. General installation privacy, security, attendance, backup and recovery guidance remains available.

Private controller templates accept optional `LANCERLOGIN_DATABASE_NAME`, passed as `DATABASE_NAME`. The default remains the slug-derived name. Resource verification continues checking the actual account, database name and UUID, and Worker binding together. A cosmetic rename remains a separate operator procedure and never creates or copies D1.

## Update

Use the supported backup-first dashboard web update from v1.0.2. Confirm the downloaded entire-installation backup before starting the pinned official release. Verify direct API health, dashboard release identity and same-origin proxy health after completion. Physical kiosk updates are separate; this patch does not require upgrading an already installed v1.0.2 kiosk.

## Verification boundary

Release publication requires the complete local gate, exact-commit public Verify CI, strict dependency audit, browser smoke and Linux root-owned kiosk artifact checks. Release packaging verifies both ARM archives, their checksums, the installer and extracted service. Local and synthetic checks do not establish physical scan, enrollment or queued-attendance behavior.
