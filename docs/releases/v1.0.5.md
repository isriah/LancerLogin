# v1.0.5 - Reliable dashboard release discovery

Dashboard release discovery now runs through the authenticated same-origin API instead of contacting GitHub directly from the browser. Browser restrictions on GitHub no longer prevent the updated dashboard from checking for releases.

Successful checks use a bounded fifteen-minute cache with concurrent request coalescing. Failed checks distinguish provider rate limits, timeouts, network failures and invalid releases, respect provider retry times, and display the last successful check separately from the last failed attempt. An old browser discovery cooldown does not carry into the new discovery cache.

## Data and configuration

There are no database migrations, new secrets or new installation settings. The private deployment controller is unchanged. Preparation still independently validates a complete official stable release and pins its commit. The entire-installation backup, saved-file confirmation and single-dispatch safeguards remain authoritative.

## Installation and updates

New installations use the v1.0.5 installer and private deployment template. Existing installations use the supported backup-first web update. An installed older dashboard still uses its original updater: if browser release discovery is blocked, the first upgrade to v1.0.5 requires an authorized exact-release deployment through the private controller, with backup and retained-resource checks. Publishing this release does not update an installation automatically.

Physical kiosk updates are separate and require operator approval. This release includes versioned ARM64 and ARMv7 kiosk archives, the installer and SHA-256 checksums.

## Manual verification and limits

After upgrading, verify direct API health, dashboard release identity and same-origin proxy health all report v1.0.5 ready. As an Administrator, open Settings > Updates and check that release discovery succeeds even when browser access to GitHub is blocked. Reloading must not confirm a saved backup, and stale metadata must not authorize preparation.

Discovery caching and request coalescing are bounded within each Worker isolate, not a global provider quota lock. Provider outages can still temporarily prevent discovery, and legitimate provider cooldowns remain respected. Automated verification and Linux extracted-artifact checks do not establish live installation, physical sensor or installed-Pi operation.
