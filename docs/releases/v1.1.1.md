LancerLogin 1.1.1 makes Discord attendance notices easier to discuss and cleans them up automatically. It also keeps meetings visible during a reporting failure and improves update discovery reliability.

## Bugs fixed

- Dashboard meetings remain visible when an attendance report request fails, and the report performs less repeated calculation work.
- Release discovery uses the installation's existing update credential when available, reducing failures caused by GitHub's shared anonymous rate limit.
- The roster attendance-rate retry control now follows the dashboard theme. **Add member** and **Bulk edit** stay together in the intended order on desktop and mobile.
- Fingerprint maintenance preserves the final enrollment and recovery guidance when an older display request finishes late.

## Features added

- Each Discord attendance notice opens a question thread. Failed thread creation is retried, and the notice is deleted after its contest window expires.

## Features removed

None.

## Installation and update

1. Back up the entire installation before updating. In **Settings → Updates**, use **Back up and begin update**, download and confirm the backup, then choose **Start update to v1.1.1**. Verify the dashboard and API report v1.1.1 after completion.
2. Give the Discord bot **Create Public Threads** and **Manage Messages** in the attendance channel. Members who should use the question threads need **Send Messages in Threads**.
3. If v1.1.0 reports that GitHub release discovery is rate limited, wait until the displayed retry time and check again. After v1.1.1 is installed, configured installations use their existing update credential for later release checks.

This release applies migration 0033 to track Discord attendance thread creation. It does not change fingerprint templates or require attendance data restoration.
