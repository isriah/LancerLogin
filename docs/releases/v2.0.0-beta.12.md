# LancerLogin v2.0.0-beta.12

This beta introduces module plugins. Optional modules are now built from their own repositories, so they can be released and updated separately from LancerLogin. Outreach Participation is an official plugin that every installation includes by default, so its users keep the same pages, settings and data with no action. Carpool is now an opt-in plugin: an installation that uses Carpool must add it before updating, as described below.

## Bugs fixed

- Creating an installation with **Latest stable** no longer fails partway through because the installation workflow ran scripts that older stable releases do not contain.
- A new installation with an empty roster no longer stays on the module setup screen. Module setup now offers **Finish setup later**, and a notice on each page reopens the unfinished setup.
- **Settings > Modules** no longer discards unsaved changes or closes the disable review while the page refreshes in the background.
- When an update is refused because a module in use would be removed, the update keeps that specific reason instead of a general preflight failure, and the diagnostic run log names the module.
- **Settings > Modules** shows the **Not deployed** badge only when plugin changes are waiting to be deployed, shows a plugin's release track only when the plugin selection could be read, and explains that changing plugins from the dashboard needs the optional module selection token while installed plugins keep working without it.

## Features added

- Module plugins. Administrators can add, upgrade and remove plugins in **Settings > Modules > Plugins**, choose a **Stable** or **Nightly (testing only)** release track for each plugin, and limit which plugin sources can be selected. Installation, web updates and backups include the selected plugins. See [module plugins](../MODULE-PLUGINS.md).
- Outreach Participation is now the official Outreach plugin and is included by default. Existing Outreach pages, settings, permissions, reports and data carry over unchanged.
- Carpool is now an opt-in plugin. An installation includes it by listing it in `lancerlogin.modules.json`. **Settings > Updates** refuses an update that would remove a module still in use and offers **Keep Carpool (add plugin)** or **Remove Carpool**.

## Features removed

- Carpool is no longer built into LancerLogin. Installations that use it must add the Carpool plugin, as described below.
- The Carpool plugin no longer reads the `CARPOOL_GEOAPIFY_KEY` deployment variable.

## Update an installation that uses Carpool

This applies to installations on v2.0.0-beta.11 or earlier that have Carpool enabled, or disabled with data still retained. These dashboards cannot check for modules that moved into plugins. If the Carpool entry is missing, the update stops before it changes anything, the v2.0.0-beta.11 dashboard shows only **Update failed**, and the diagnostic workflow run names the module.

1. Before preparing this update, open the private deployment repository on GitHub and go to `main`.
2. Open `lancerlogin.modules.json`, or create it if it is missing, and add the Carpool entry from [`scripts/known-modules.json`](../../scripts/known-modules.json) in this release, with its `id`, `source` and `commit`:

   ```json
   {
     "format": 1,
     "modules": [
       { "id": "carpool", "source": "https://github.com/isriah/lancerlogin-carpool.git", "commit": "4471b8c118ac392376e9b2c30a876c16a4eab48a" }
     ]
   }
   ```

3. Commit the change to `main`, then prepare the update in **Settings > Updates** as usual.
4. If Carpool location lookup used the `CARPOOL_GEOAPIFY_KEY` deployment variable, save the Geoapify API key again in **Settings > Modules > Carpool** after the update, then remove the variable.
5. Confirm that **Settings > Modules** lists Carpool as installed and that its pages and meeting links open.

If the update already failed for this reason, nothing was changed. Add the entry as above and prepare the update again.
