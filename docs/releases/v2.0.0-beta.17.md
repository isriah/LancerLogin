# LancerLogin v2.0.0-beta.17

This beta makes a new installation much easier to set up. The installer explains every problem with a clear fix, dashboard updates no longer have to be configured before the first install, and first-time setup now signs you in, adds your first roster member and ends with a clear list of next steps. Existing installations need no action.

## Bugs fixed

- After creating the first Admin with a username and password, you are now signed in straight away instead of being asked to sign in again.
- Attendance setup no longer sends you to the Roster page part-way through. It now includes a Roster step where you can add a member or import a CSV.
- Optional setup steps you skip no longer show "Action needed", and the setup status no longer says both "complete" and "unavailable" at once.
- Page tours no longer open on top of setup or straight after it finishes.
- After you stop the browser simulator on the Kiosks page, you can start it again with **Start simulator**.
- The Add physical kiosk installer now matches the release your dashboard runs, instead of always downloading the latest stable kiosk.
- If the installer stops part-way through a new installation, running it again with operation **resume** finishes the job, and it no longer leaves an unused database behind.
- Changing `LANCERLOGIN_SETUP_CODE` and running the installer with **resume** now takes effect when no Admin has been created yet.
- Form fields in first-time setup, Choose modules and the roster dialogs are now labelled for screen readers, and the sign-in method choice works as a keyboard radio group.

## Features added

- The dashboard update token `LANCERLOGIN_WEB_UPDATE_TOKEN` is now optional during installation. Without it, update by running **Install or upgrade LancerLogin** with operation **upgrade**; **Settings > Updates** explains how to turn on one-click updates later.
- LancerLogin now reads a GitHub token's expiry date from GitHub, so the `WEB_UPDATE_TOKEN_EXPIRES_AT` and `MODULE_SELECTION_TOKEN_EXPIRES_AT` variables are no longer needed. You can delete them. When a token expires or is revoked, the dashboard says so and explains how to replace it.
- **Settings > Updates** has a new **Setup status** panel for the update token, the update controller workflow and the plugin management token, with links to the GitHub pages that fix each one, and a warning 14 days before the update token expires.
- Update errors now name the exact secret or workflow to fix.
- The installer checks your Cloudflare token's permissions, your workers.dev subdomain and the dashboard address before creating anything, and every failure shows a short explanation and fix.
- The installer's summary lists the three environment variables to add for future updates, including the database ID.
- First-time setup has a time zone list, Choose modules starts with Attendance selected and labels plugins, the setup fields have help text with examples, and a new **Attendance is ready** screen links to your next steps.
- The Add physical kiosk dialog gives step-by-step instructions with a copyable install command and pairing key.
- The empty roster shows **Add member** and **Import CSV** buttons.

## Features removed

- The installer's **original template release** option. The installer always installs the latest stable release.
- The **Community Edition** label on the sign-in screen.
