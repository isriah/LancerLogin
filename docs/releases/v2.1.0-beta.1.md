# LancerLogin v2.1.0-beta.1

Member labels get their own page, and Admins can link a label to a Discord role and keep that role in sync without leaving the dashboard. The roster's bulk edit, CSV import and attendance start dates are easier to use, and dashboard pages load faster.

## Features added

- **Labels page.** Labels have their own tab in **Settings > Modules > Attendance > Labels**. Each label shows its current members (linking to the Roster filtered by that label), its attendance rule, the meetings that target it and its Discord role. Admins can create, rename, retire and restore labels there. Attendance rules stay on the **Attendance rules** tab.
- **Discord roles from the dashboard.** Admins choose a role for a label from a list of the server's roles. Roles the bot can't manage are listed with the reason, and role and label names no longer need to match. **Create labels from Discord roles** creates and links labels in one step, and `/label @ROLE` in Discord still works. Linking changes nobody's roles until you sync.
- **Role sync status.** An icon next to each linked role shows whether it is in sync, has label changes since the last sync, is syncing, failed or was never synced. Hover over, focus or tap it for details. **Sync all linked roles** previews and syncs every linked label at once, and a failed sync offers **Retry failed**. Each label's **More** menu holds **Rename**, **View last sync**, **Unlink role** and **Retire label**. After label changes in Roster, the dashboard links back to review role sync.
- **Roster bulk edit.** **Bulk edit** opens a sidebar for the ticked members, with a review dialog before changes apply. On phones it is a bar at the bottom of the screen.
- **Roster imports.** One **Import** menu offers **Members from CSV** and **Labels from CSV**. The roster import explains its columns, offers **Download template** and accepts common header names such as `Student ID`, `First` or `Surname`. The label CSV accepts loose headers too and has its own template. **Add member** now adds one person.
- **Label assignment.** The effective date is optional wherever labels are assigned, and a blank date means today. Previews name each member.
- **Attendance start dates.** The roster's Add and Edit dialogs show each member's effective attendance start date, with a **Custom date** checkbox to change it.
- **Saved credentials.** Each integration with saved credentials shows the date they were saved and a **Replace credentials** button, never the values themselves.
- **Plugin versions.** Plugin management shows each plugin's installed version, the latest version on its track and whether an update is available.
- **Installation repository files.** **Settings > Updates** reports when the installation repository's workflow and script files are out of date, and **Update repository files** opens a pull request with the release's versions.
- **Faster pages.** The API Worker deploys with Smart Placement by default, and pages make fewer sequential database round trips. An optional `LANCERLOGIN_WORKER_PLACEMENT_REGION` setting pins a region instead.

## Bugs fixed

- A Discord absence notice is withdrawn when its meeting's times, required setting or audience change while members can still contest it, and members who are checked in can no longer contest an absence.
- When a Discord role can't be linked or synced, the message names the role, the problem and how to fix it.
- Google Calendar setup reports specific reasons, such as a disabled API, missing permissions or no access to the selected calendar, instead of a generic error. Browsers no longer autofill saved passwords into integration credential fields.
- Primary buttons, such as **+ Add meeting** and **Open Attendance setup**, keep the accent color.
- The Integrations page checks Discord command setup when it opens instead of waiting for the next maintenance pass.
- Contest review links each member's name to their roster page.
- A beta Core now satisfies a plugin's `core` range when the range covers its release, so plugins that support 2.x, including Outreach, Carpool and Guest Visits, keep working on 2.1 betas. An upper bound such as `<3.0.0` still excludes 3.0.0 betas.

A blank attendance start date now means the date the member was added to the roster everywhere, including check-in. Reports already worked this way.

## Features removed

- The Labels card and Discord roles section on the **Attendance rules** tab. Both moved to the **Labels** tab.
- **Import CSV instead** in the **Add member** dialog. Use **Import > Members from CSV**.
- The warning about GitHub production approval in **Settings > Updates**. Update runs that GitHub pauses for approval are still handled.
