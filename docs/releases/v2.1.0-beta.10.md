# LancerLogin v2.1.0-beta.10

This beta makes waiting kiosk PIN requests hard to miss, with a **PIN requests** count in the top bar and on each kiosk's row, and lets a Beta-track installation upgrade to the newest beta from the **Install or upgrade LancerLogin** workflow without the update token. Entire-installation backups work on Cloudflare's free plan again, the Raspberry Pi kiosk's Wi-Fi keyboard can type any password, and logos of any shape fit their frame. It also fixes two-way Discord labels that stopped syncing, PIN lockout under bursts of tries, and several dashboard, web kiosk and Pi kiosk problems.

## Updating to this release

- **Update each Raspberry Pi kiosk after the dashboard.** The Wi-Fi keyboard, the queue repair, the **Set member PIN** fix, the logo frame, the new wording and stating its release at pairing arrive on a Pi kiosk only with its own update (**Update kiosk** on **Manage kiosk**). Web kiosks update with the dashboard.
- **Update your deployment repository's workflow file to get the new workflow behaviour.** The `latest beta` choice and the rule that an expired optional token no longer blocks an upgrade live in your private repository's own copy of **Install or upgrade LancerLogin**, which a dashboard update doesn't change. After updating to this release, choose **Update repository files** in **Settings > Updates**, or copy the file by hand as described in [Keep your repository's workflow files current](https://isriah.github.io/LancerLogin/updates.html#repository-files-by-hand). If your token has already expired, the old workflow file still stops at it: delete the `LANCERLOGIN_WEB_UPDATE_TOKEN` secret, or copy the new file by hand.
- The included Outreach plugin moves to v1.3.1 with the update. There are no database changes.

## Bugs fixed

- **Two-way Discord labels finish syncing.** With three or more two-way labels, a queued role change could be picked up and put back every second without changing anyone, and the other labels never got their turn. Queued role changes now finish for every label. A sync started by the two-way check now shows **Syncing** with its progress on **Settings > Labels**, and **Sync stuck** with **View sync** if no change has gone through for 15 minutes.
- **Entire-installation backups work on Cloudflare's free plan again.** A backup read each table separately, which went past the free plan's limit of 50 requests at a time, and further with plugins. It now reads everything in one step, which also makes it one consistent snapshot even while people are signing in.
- **Restoring no longer brings back signed-out sessions.** A restore reset every account's sessions, so a session that had been signed out or revoked could work again. Now a restore signs everyone else out. The Admin who restores stays signed in, as long as the backup holds their account as an active one. A restore also clears scan-check records, as deleting the installation does.
- **Meeting CSV import accepts notes-only updates.** **Import CSV** refused an update to a meeting that sat close to another one, even when the update didn't change its times. As when editing a meeting, only a row that adds a meeting or changes its times is checked against the early arrival and late scan allowances.
- **PIN lockout holds at its number.** With **Kiosk PIN lockout** set to 3 or 4, PINs sent at the same moment could have up to 5 tries checked before the lock started. The lock now starts at exactly the configured number.
- **Require PIN works right after pairing.** A Pi kiosk now states its release when it pairs, so **Require PIN** can be turned on straight away instead of after its first check-in. The amber notice beside a disabled **Require PIN** checkbox now says "Update this kiosk to use Require PIN" instead of telling you to use Require PIN, and the separate line repeating it is gone.
- **A module change commits only what you reviewed.** In **Settings > Modules**, a release lookup that finished after **Review change** could change the commit, so **Commit change** pinned a commit other than the one shown. **Commit change** now sends exactly what was reviewed, and **Review change** waits for the lookup. A commit that isn't compatible with your installation is now refused with the reason, even if requested directly, instead of failing during the next update.
- **Kiosk updates say what went wrong.** **Update kiosk** reported "No compatible official kiosk release is currently available" for every failure. It now says whether GitHub is limiting release checks, didn't answer in time, couldn't be reached, returned an error or sent an answer that couldn't be read, and when to try again. That last message is now kept for when no compatible release exists.
- **The Pi kiosk's Wi-Fi keyboard types any password.** It had only lowercase letters, digits and ten symbols, so a touchscreen-only kiosk couldn't join a network whose password has a capital letter, a space or most punctuation. It now has **Shift** (tap twice for **CAPS**), a **!#?** key for every symbol, and **Space**. **Show** beside the password field reveals it to check it. On small screens, **Connect** is no longer pushed off screen.
- **The kiosk's network settings say how to reset a forgotten PIN.** The screen used to point to a setup tool that doesn't exist. It now says "If you forget it, use Reset network PIN on this kiosk's Manage page in the dashboard. The kiosk must be online for that."
- **A damaged queue file no longer stops a Pi kiosk.** If writing a scan to the kiosk's waiting queue failed part-way, for example on a power cut, the kiosk could stop recording at its next start. It now sets the damaged line aside, keeps every complete scan in order and carries on.
- **Set member PIN after a failed save.** On a Pi kiosk, typing the PIN again after a failed save gave "The two PINs don't match". It now starts over at **Choose a PIN** and shows the reason.
- **Logos of any shape fit their frame.** A square or tall logo spilled out of its frame in the top bar, the sign-in header, the **Settings > Organization** previews and the Pi kiosk's screen, where it could cover the **Logo contrast background** choices. Every logo is now scaled to fit without cropping.
- **Rejected scans show plain reasons.** **Rejected scans** under **Debug tools** on the **Kiosks** page showed codes such as `pin_required`. They now read, for example, "This kiosk requires a PIN, and the scan had none".
- **Web kiosk screens are no longer cut off.** On phones and short landscape screens, the top of a tall screen, such as **Set member PIN** search with several results, could be hidden and unreachable. Screens now start at the top and scroll, and keys and result rows are easier to tap.
- **Error messages get keyboard focus.** After a failed save in **Settings > Access**, a meeting or roster import or module access, focus sometimes stayed on the page instead of moving to the error, so screen-reader users weren't told. It now moves every time.
- **Tab moves one step in meeting times.** In the meeting form's **Start time** and **End time**, Tab after typing an hour skipped the minutes. It now moves to the next part of the time. Outreach v1.3.1 makes the same fix in **Event start time** and **Event end time**.
- **Integration settings keep what you're typing.** **Settings > Integrations** reloaded every 2 seconds while a Discord verification waited, replacing Discord channel and anomaly report fields being edited. It now keeps fields you have changed until you save.
- **Smaller fixes.** **Reports**: the period chip and the column filter button are easier to tap, and a fixed period with an impossible date says "Choose a valid report period." instead of showing a server error. Meeting import's **Skip** and **Update** choices and the bulk roster sheet's **Clear** and **Change** links are easier to tap.
- **Documentation.** The privacy pages now say that after **Reset all fingerprint mappings**, **Erase unlinked fingerprints** erases only templates that were never shared through cloud storage. New and retaken screenshots cover web kiosks, Discord codes, rejected scans, PIN requests and the Labels page.

## Features added

- **PIN requests in the top bar and on the Kiosks list.** While a member waits for PIN approval, Admins and Operators see a **PIN requests** count in the top bar, beside **Reviews**. It opens every waiting request by kiosk, with **Approve** and **Decline**. The kiosk's row on **Kiosks** shows its count, such as "2 PIN requests", and opens its **Manage kiosk** page. The kiosks' waiting screens now say an Operator or Admin approves in the dashboard.
- **Upgrade to the newest beta without the update token.** **Install or upgrade LancerLogin** has a second release choice, `latest beta`, for the `upgrade` operation on a Beta-track installation. It installs the newest complete official release, beta or stable. Neither `latest beta` nor `latest stable` ever installs an older release than the one running. This needs the new workflow file (see above).
- **An expired optional token no longer blocks an upgrade.** If the optional `LANCERLOGIN_WEB_UPDATE_TOKEN` has expired or been revoked, `upgrade` and `resume` now warn and continue without it. A new installation still stops, and the error says the token is optional and the secret can be deleted. This also needs the new workflow file.
- **"Discord users not on the roster" moved to the Labels page.** It's now a section in the **Discord roles** card on **Settings > Labels**, shown to Admins without Debug mode, while Discord is verified and at least one label syncs two-way. It's no longer under **Debug tools** on **Kiosks**.
- **Logo frames narrow to fit.** A square, tall or thin logo now sits in a narrower frame instead of a wide, mostly empty one, and the organization name moves closer. Wide logos look the same as before.
- **Leaderboard dates explain themselves.** The Leaderboard's **To** date can't be set before the attendance baseline, and a date typed earlier shows why there are no results and how to fix it. A **From** date after **To** shows "Choose an end date on or after the start date."
- **Outreach v1.3.1.** The included Outreach plugin is now v1.3.1: Tab moves through the event time fields in **Create Outreach activity** and **Edit Outreach activity**, and the **Outreach labels (optional)** checkboxes take less room.

## Features removed

None.
