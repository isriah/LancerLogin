# LancerLogin v2.1.0-beta.11

This beta is mostly about staying inside Cloudflare's Free plan as a team's data grows. Backups and restores now move in small parts, so a multi-season installation can be backed up and restored from the dashboard. Calendar events for meetings are queued with each change and sent in the background, so a long series, a bulk delete or **Sync all meetings** no longer needs more requests than the Free plan allows at once. It also fixes roster imports that unlinked Discord accounts, start dates and member-facing dates that used the wrong day for teams outside UTC, several Raspberry Pi kiosk problems around the fingerprint reader, Wi-Fi and power cuts, and a number of dashboard problems. The **Install or upgrade LancerLogin** workflow now checks that the installation answers after it finishes, and the included Outreach plugin moves to v1.4.0.

## Updating to this release

- **Update each Raspberry Pi kiosk after the dashboard.** The kiosk fixes below (fingerprint reader, **Erase unlinked fingerprints**, Wi-Fi, the network settings PIN and the new **Diagnostics** rows) arrive on a Pi kiosk only with its own update (**Update kiosk** on **Manage kiosk**). Web kiosks update with the dashboard. Nothing needs to be paired or enrolled again.
- **A one-time start-date correction runs by itself.** Older versions stored some members' participation start as the date in UTC, which for a member added in the evening west of UTC (or the early morning east of it) is a day off the team's own date. Within a few minutes of the update, LancerLogin begins correcting those dates, a few members at a time. A member's date is changed only when the change cannot lower their attendance record: they lose no presence, gain no absence and fall below no weekly target because of it. Start dates an Admin changed are not touched, and a member for whom the change would make no difference, or would count against them, keeps the date they have. There is nothing to do.
- **Backups and restores now run in parts, with a warning before a very large restore.** The backup file is the same as before, and older backups still restore. Cloudflare's Free plan allows 100,000 database rows to be written a day across the account, and a restore writes several rows for every record, so a backup of more than roughly 15,000 records passes that allowance. Before a restore estimated to write more than 80,000 rows, the dialog now says about how many and asks whether to continue. If the account passes the allowance, Cloudflare stops answering every database query until 00:00 UTC: the dashboard and every kiosk stop working until then, sign-in included. On the Free plan, restore a large backup when the installation can be out of use until then, or move the account to a paid plan first.
- **Update your deployment repository's workflow file to get the new health check.** The health check and the clearer Cloudflare token messages live in your private repository's own copy of **Install or upgrade LancerLogin**, which a dashboard update doesn't change. After updating to this release, choose **Update repository files** in **Settings > Updates**, or copy the file by hand as described in [Keep your repository's workflow files current](https://isriah.github.io/LancerLogin/updates.html#repository-files-by-hand).
- The included Outreach plugin moves to v1.4.0 with the update, with no database changes of its own. A verified Discord connection adds its new `/outreach-report` command by itself within a few minutes.
- A preview of a rule or meeting change that was open during the update must be previewed again before it can be applied.

## Bugs fixed

- **Long series, bulk changes and Sync all fit the Free plan.** Saving, editing, deleting or restoring meetings did the Google Calendar and Discord work inside the same request. With a long series, a bulk delete or **Sync all meetings**, that went past the Free plan's limit of 50 requests at a time, and calendar events could be left unsent. Calendar changes are now saved together with the meeting change and sent in the background (see Features added).
- **Deleting meetings and attendance removes their calendar events.** Deleting **Meetings and attendance** in **Settings > Data**, or restoring a meetings backup, left the removed meetings' Google Calendar and Discord events behind. They are now removed in the background.
- **Roster import no longer unlinks Discord accounts.** Importing a CSV without a Discord user ID or Email column, or with blank cells, cleared those values for every member in the file. A missing column, a blank cell or an invalid Discord user ID now keeps what the member has, and a new value replaces it. The preview shows the values each member will end up with. An import can no longer clear an email or Discord link.
- **A new member's start date uses the team's own day.** For a member added without a start date, LancerLogin worked out the start from the UTC date. A member added in the evening west of UTC had that evening's meeting left out, and east of UTC the previous day's meeting counted. The start now follows the organization's time zone, in attendance, reports, the kiosk's check and the roster's **Edit roster member** and **Add member** dialogs. Dates stored by older versions are corrected once (see above).
- **Dates sent to members use the organization's time zone.** The meeting date in the missed-meeting email, the report email, the Discord anomaly report and the `/attendance-report` list of missed meetings was the UTC date. Report CSV file names used the UTC date too, which was tomorrow's date every evening in the Americas.
- **Large backups and restores work on the Free plan.** Reading or writing a whole backup in one request used several times the processing time the Free plan allows per request, and a backup file over 10 MiB could not be restored from the dashboard at all. Both now move in parts (see Features added).
- **Rule and meeting change previews are much faster.** Previewing the effect of an attendance rule or meeting change on a full team used far more processing time than the Free plan allows per request. Previews and reports now do the same work in a small fraction of the time, with the same results.
- **A failed attendance email can be sent again.** After a send failed or was interrupted, sending the same missed-meeting or report email again failed every time, and an interrupted send could block disabling the Attendance module. A failed send can now be retried, and one stuck for 15 minutes is marked as failed.
- **Fingerprint resets no longer stop at 64.** After 64 resets, every further **Reset all fingerprint mappings** was refused. Finished resets are now cleared away.
- **Outreach no longer shows "Update not finished" after a clean update.** Two background checks running at the same moment after an update could leave **Update not finished** on a module in **Settings > Modules** although its update had completed, and it never cleared. It no longer happens, and an installation already showing it clears by itself after this update.
- **Commit change accepts only the change you reviewed.** In **Settings > Modules**, **Commit change** is now refused unless it matches a review made by the same Admin in the last 30 minutes, with a message to review the change again. The button is also no longer disabled for a change the server would accept.
- **Two requests at the same moment can't both win.** Two overlapping meetings created or rescheduled at once could both be saved, the same meeting CSV import committed twice at once added every meeting twice, and a kiosk asking twice for a member's PIN setup made two requests. One now succeeds and the other gets the usual message. Two overlapping weekly targets or attendance rules saved at once now give the normal "cannot overlap" message instead of a server error. Turning a module on or off in **Settings > Modules** at the same moment as another change could report a conflict although the change had been saved; it is now saved whole or not at all.
- **Reviews stays in the top bar.** One failed background refresh could hide **Reviews** or close an open review dialog until the page was reloaded. The dashboard now keeps what it last knew and tries again.
- **Mark reviewed says when a scan was already reviewed.** It now says the scan was already reviewed, that its existing note was kept and that attendance was not changed.
- **Discord code lockout counts every wrong code.** A wrong Discord code sent at the same moment as a correct one could go uncounted.
- **Tab moves one step in every date field.** In the meeting form's **Date** fields and every other date field in the dashboard, Tab after typing the month or day skipped the next part. The Attendance setup meeting step's date and time fields are fixed the same way.
- **Discord absence notices recover from interruptions.** A notice interrupted part-way is taken up again after ten minutes without mentioning anyone twice. A notice or anomaly report Discord keeps refusing is retried with growing delays and given up after 16 attempts; **Send Discord absence notice** on the meeting still sends it.
- **The Discord kiosk status message keeps up without extra work.** It is now updated in the background instead of on every kiosk heartbeat. It changes within seconds when a kiosk comes back online or reports a different reader state or release (within five minutes on installations whose background work runs only every five minutes), shows a kiosk as offline about two to seven minutes after its last heartbeat, and is restored within an hour if deleted in Discord.
- **Background work writes less.** A two-way label check that finds nothing changed no longer rewrites its whole list of Discord users not on the roster, and each scan writes one database row fewer, which leaves more of the Free plan's daily allowance for scans.
- **Pi kiosk: Erase unlinked fingerprints works after a reset.** After **Reset all fingerprint mappings**, **Erase unlinked fingerprints** erased none of the templates the kiosk had saved to or received from cloud storage. It now erases them. A template linked to a member, or one belonging to an import that hasn't finished, is never erased.
- **Pi kiosk: one bad read no longer ends an enrollment.** A faint or garbled image during enrollment ended it; the kiosk now asks for the image again, up to five times in a row. While scanning, one garbled read no longer shows "Reader offline": that appears after three reader errors in a row, or at once when the reader doesn't answer.
- **Pi kiosk: reader answers stay matched to their commands.** A reply that arrived after the kiosk had stopped waiting for it could be taken as the answer to the next command, and stray bytes could be read as a reply. The kiosk now discards leftovers and checks each reply before using it.
- **Pi kiosk: the reader's own capacity is used.** The kiosk refused fingerprint slots from 200 up on every reader. It now asks the reader how many it holds and uses that, and keeps 200 when the reader doesn't say.
- **Pi kiosk: Wi-Fi problems are reported sooner.** A wrong Wi-Fi password sat on "Connecting…" for 30 seconds; it is now reported as soon as the network refuses it. A password shorter than 8 characters is refused straight away, and a network that signs in with a username (802.1X) is marked **Needs a username · not supported** in the list instead of failing after a wait.
- **Pi kiosk: a power cut can't lock or unlock network settings.** A network settings PIN file damaged by a power cut locked everyone out of the kiosk's network settings and maintenance, and one kind of damage let anyone at the kiosk choose a new PIN. The kiosk now keeps a backup copy and restores the PIN from it. If both copies are damaged the PIN stays locked, and the screens say to use **Reset network PIN** in the dashboard.
- **Smaller fixes.** The column filter button beside an info tip in **Reports** is easier to tap. Meeting times are stored in one standard form. Changes to branding, labels, members and a few other settings are now saved together with their audit entry.
- **Documentation.** The setup and update pages now say correctly which repository variables **Install or upgrade LancerLogin** reads: it needs none of `LANCERLOGIN_INSTALLATION_SLUG`, `LANCERLOGIN_DATABASE_ID` or `LANCERLOGIN_API_URL`, which only one-click updates and **Refresh web update credential** use. New sections cover backups and restores in parts, calendar delivery, entries a kiosk set aside and the network settings PIN backup.

## Features added

- **Backups and restores in parts.** The dashboard downloads a backup and uploads a restore in small parts, with progress shown during a restore. A restore file may be up to 100 MiB instead of 10 MiB; the limit of 150,000 records is unchanged. Nothing is replaced until every part has arrived and been checked, and the data is still replaced all at once or not at all. If the connection drops, the dashboard continues with the parts that are missing.
- **A warning before a restore that would use most of a day's write allowance.** See "Updating to this release". **Restore anyway** continues.
- **Calendar events are sent in the background.** A meeting change queues its Google Calendar and Discord events, and the dashboard says they are queued. Removals go first, then the soonest meetings. They are usually sent within seconds; on an installation whose background work runs only every five minutes, five Google Calendar and three Discord events are sent each time, and the dashboard says how many are waiting. **Sync all meetings** queues every current and upcoming meeting in one go. Turning an integration back on, or verifying it again, queues what was changed while it was off. A calendar event that can't be removed is retried for about three days and then counted on the integration card as needing another attempt.
- **Kiosk storage problems show in Diagnostics.** **Manage kiosk > Diagnostics** shows **Network settings PIN** when a Pi kiosk restored its PIN from the backup copy or can't read it, and **Scans set aside** or **Enrollment reports set aside** when the kiosk found unreadable entries in a waiting queue and kept them for recovery. The kiosk's maintenance screen shows the same.
- **A health check after installing or upgrading.** **Install or upgrade LancerLogin** now ends by checking, for up to two minutes, that the installation and its dashboard answer on the release just installed, and adds **Health check passed** to the run summary. If not, the run fails and says which address answered and with what. This needs the new workflow file (see above).
- **Clearer Cloudflare token errors in the workflow.** When Cloudflare rejects `CLOUDFLARE_API_TOKEN`, the run now says the token has probably expired or been deleted and what to replace it with, and says separately when Cloudflare simply didn't answer. This also needs the new workflow file.
- **Release notes are formatted.** **Settings > Updates** shows release notes with their headings, lists, bold text and links instead of as plain text.
- **Confirmation before unpinning a report.** The × on a pinned report tab now asks first and says the report stays saved in **Browse reports**. The × that removes an imported browser view asks too, because that view is deleted.
- **Outreach v1.4.0.** The included Outreach plugin adds the `/outreach-report` Discord command, which privately shows a linked member their own Outreach participation summary.

## Features removed

None.
