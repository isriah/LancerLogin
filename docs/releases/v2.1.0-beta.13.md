# LancerLogin v2.1.0-beta.13

This beta gives the comments a module adds in Notion a proper author name. Until now they appeared under "Unnamed Bot". They now appear under the module's name, such as **Part Requests**, and a module can let an Admin choose a different name. It also stops an installation without dashboard updates set up from reporting an error on every page.

## Bugs fixed

- **Notion comments name their author.** A comment a module added through the shared Notion connection showed "Unnamed Bot" as its author. It now shows the module's name, such as **Part Requests**. Notion adds the connection the comment came through after the name.
- **No error on every page when dashboard updates are not set up.** On an installation with no deployment workflow address, the dashboard's check of the running release failed twice on every page, and **Settings > Updates** showed the installed release as **Unavailable**. The check now answers normally, and the Updates page shows the installed release and still explains how to set dashboard updates up.

## Features added

- **A module can offer its own comment name.** A module that comments in Notion can show **Name shown on comments** on its settings page. An Admin types the name Notion should show for that module's comments, or leaves it blank to use the module's name. Each module has its own name. Entire-installation backups carry the names; older backups restore with none set. The included modules don't comment in Notion, so none of them shows the field.
- **For plugin authors:** module SDK 1.9.0 adds `NotionCommentNameField`, which a plugin that declares `comments.create` places on its Admin settings page with its own module ID. Core stores the name and applies it to every comment that plugin creates; a plugin built for SDK 1.8.0 needs no change and gets its module's name by default.

## Features removed

None.
