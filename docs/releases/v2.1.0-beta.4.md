# LancerLogin v2.1.0-beta.4

This beta includes the Outreach plugin v1.2.0, so members can now log Outreach time that has no Staff-created activity. It adds **Team support** and **Other service** to the public participation form, with a service date and minutes instead of start and end times. When a member adds a team that isn't listed yet, the form checks its number with FIRST and fills in its name, and Staff review the teams members add. Plugins can also require an earlier plugin release on the upgrade path, so an update can't skip a release that moves data.

## Bugs fixed

None.

## Features added

- The included Outreach plugin is now v1.2.0.
- **Team support and Other service on the public form.** The public participation form starts by asking **What are you logging?**: a **Scheduled activity** Staff created, as before, **Team support** or **Other service**. Team support and Other service take a service date inside the reporting window and 1 to 1,440 minutes, with no start or end time, and count right away.
  - **Team support** names a supported team, or **My team is not listed - add it** with the team number, program and name. The entry joins that team's Team Support activity for the date, which Outreach creates when there is none.
  - **Other service**, such as STEM tutoring, takes a short description. The entry joins the Other Service activity with that description on that date, which Outreach creates when there is none.
  - Staff can edit or void these entries like any other. Staff screens show **Duration only** where other entries show start and end times, editing asks for **Minutes**, and reports show N/A for their start and end times. Duration-only entries never count as overlapping other participation.
- **FIRST check for new teams.** A new team's number is checked through the FIRST connection on **Settings > Integrations > FIRST**. When FIRST finds the team, its name fills in, with the season FIRST found it in, for example "Name from FIRST (2026 season)." When FIRST has no such team, the form warns, and the member can still add the team with the name they type. When FIRST can't answer, the member types the name. An entry is never refused because of FIRST.
- **Member-added teams.** Teams members add appear in **Settings > Outreach > Supported teams** marked **Added by a member**. The **Added by** filter shows **Members, not yet reviewed**, and **Mark reviewed** clears the mark once Staff have checked the team.
- **Required upgrade path for plugins.** A plugin can list earlier migrations in `lancerlogin.upgradeRequiresMigrations`, so an installation that already has the plugin must install the release that adds them first. **Settings > Modules** refuses such an update with a message that names the migration to install first. If such a build is deployed anyway, LancerLogin applies none of that plugin's new migrations and keeps retrying until the earlier release is installed; meanwhile the plugin's new code runs against its older database tables. New installations are unaffected. Plugins that use the key need this LancerLogin release or later. See [Migrations](https://github.com/isriah/LancerLogin/blob/main/docs/PLUGIN-AUTHORING.md#migrations) in the plugin guide.

## Features removed

- The **Staff sign in** link at the bottom of the public Outreach form. Staff sign in from the dashboard as before.

## Updating

Updating applies Outreach's first database migration automatically: existing supported teams count as added by Staff, and existing entries keep their start and end times. Entire-installation backups made with this release can't be restored into an installation that runs an older Outreach release.
