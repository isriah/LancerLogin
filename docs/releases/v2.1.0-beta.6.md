# LancerLogin v2.1.0-beta.6

This beta makes updates and the dashboard more dependable. **Check for updates** now finds a newly published release straight away, the dashboard no longer waits forever when it cannot reach its server, and a server can no longer get stuck after one interrupted request. Dashboard updates also ride out a brief GitHub outage and explain clearly when a re-run cannot retry an update. The rest of this release is internal test and tooling work that changes nothing you see.

## Bugs fixed

- **Check for updates finds new releases straight away.** In **Settings > Updates**, **Check for updates** used to return the server's saved answer, so a release published in the last 15 minutes could stay hidden. With one-click updates set up, the button now asks GitHub again, at most once a minute. **Last successful check** shows when GitHub was actually read, and after a failed check the button is available again sooner.
- **No more endless "Checking your installation…".** If the server does not answer within 15 seconds, the dashboard now shows **Setup service unavailable** or **Session check unavailable** instead of waiting forever. **Setup service unavailable** now has a **Try again** button, like the session check.
- **A server no longer gets stuck after an interrupted request.** If the first request a freshly started server received was cancelled while it checked its modules, that server could stop answering every later request, including the dashboard and kiosks, until it was replaced. It now keeps answering and finishes the check in the background.
- **Dashboard updates survive a brief GitHub outage.** The update's first check of the official release is now retried for about 30 seconds when GitHub briefly does not answer, instead of failing the update straight away.
- **Re-running an ended update no longer looks successful.** Re-running an update's GitHub workflow run never retries the update. Such a re-run now fails with `request_not_claimable` and explains how to start the update again from the dashboard, instead of passing while nothing was deployed.
