# LancerLogin v2.1.0-beta.7

This beta makes LancerLogin fit comfortably on Cloudflare's free Workers plan and makes reports easier to build and read. Sign-in now hashes your password in your browser, so the server never receives it. Kiosk PIN checks are much lighter and slow down repeated wrong guesses. Background work such as calendar sync and Discord notices now runs in small steps instead of one large pass every five minutes. Reports gain filters in the results table, a **Last month** period, **H:MM** durations and an **Attendance by label** view. Meetings can be imported from a CSV file.

## Updating to this release

- **Each local account's first sign-in after the update converts its password once.** That first sign-in takes about as long as before; later sign-ins are lighter for the server. Nothing else changes for the person signing in. Accounts restored from an older backup convert the same way.
- **Reload dashboard tabs that were open before the update.** A tab loaded before the update cannot sign in, create an account or confirm your identity; it shows "This page is out of date. Reload the page and try again." or, on the sign-in page, "Invalid username or password". Reloading the page fixes it.
- **Kiosk PIN guesses are now throttled.** After 5 wrong PINs in a row for the same member, each further wrong PIN makes the next try wait 30 seconds, then 1 minute, then 5 minutes. The kiosk shows **Please wait** with the time left. A correct PIN, or **Unlock** on the member's Kiosk PIN card, ends the wait. The optional PIN lockout setting works as before.
- **Pi kiosks enforce the throttle only after they update.** Web kiosks get it straight away with the dashboard. A Pi kiosk still on an older release checks the PIN against its own saved copy during a wait instead, as it does when offline, until it installs this release. PIN checks a kiosk makes while offline are never throttled.
- The update adds a small database table for background work, two columns for the PIN throttle and a separate reporting start date for Outreach (copied from the Attendance date), and moves background work onto a Cloudflare Durable Object with a five-minute safety check. These changes are automatic.

## Bugs fixed

- **New reports no longer start in the future.** A new custom range used to start on tomorrow's date every evening in the Americas, and a reporting start date still in the future gave new reports a backwards range with no results. Ranges now start on your installation's today, and new reports use **All history** until the start date arrives. Choosing **Operational baseline** with a future date shows a warning.
- **Attendance and Outreach have separate reporting start dates.** The Attendance date used to filter Outreach reports too. A combined Members report with columns from both now has a **Baseline** choice for which date to use.
- **Deleting a report always leaves straight away.** Deleting a report you had edited no longer asks whether to save or discard your changes. The confirmation now names the report.
- **"Last 7/30/60/90 days" saved correctly.** Choosing one of these periods could store an invalid period.
- **Discord rate-limit messages name the right feature.** A rate limit while publishing an Outreach Event no longer says "role sync", and the message says roughly when to try again instead of a fixed number of seconds that never changed.
- **Phone calendar layout.** On phones, **Import CSV** now sits in a full-width row under the month navigation, so the Meeting calendar heading no longer overflows or wraps.
- **Tooltips are left-aligned** in the Leaderboard and number columns, and report counts read "1 matching row" and "1 member".
- **Background jobs no longer run out of room.** On the free plan, the jobs at the end of the old five-minute pass could fail without notice. Each job now runs on its own in small steps, and **Stop** on **Scheduler status** pauses all outgoing messages and calendar sync and ends by itself after 24 hours (shown as "Stopped until …"). Discord events are created for meetings up to 60 days ahead and added as later meetings come within range.

## Features added

- **Import meetings from CSV.** **Import CSV** on the Dashboard, in the Table and Calendar views, previews each row as Add, Update, Skip or Error before anything is saved. **Matching rows** lets you skip or update meetings that already exist, rows with errors are skipped, and past meetings are imported without Discord absence notices. Up to 200 rows per file; dates use MM/DD/YYYY.
- **Filters in the results table.** Each filterable column has a filter button in its header, **+ Filter** adds a filter on any field, including fields not shown in the table, and filters appear as chips with **Clear filters**. The report period is a chip beside the report type, and each report is now a single card.
- **Attendance by label.** A new report preset and an **Attendance by label** choice in **Add column** add a label's whole set of columns: attendance rate, target, status, attended and counted meetings, weeks met and excused. On the Leaderboard, choosing one label with a policy ranks members by that label's rate.
- **"How this is calculated".** Rate columns and the Leaderboard explain their calculation with an example, the member profile has a **How these rates are calculated** section using that member's numbers, and each attendance policy in Settings shows an example.
- **Clearer attendance words.** Rates are now **Overall rate**, shown to one decimal place, and **Policy result**, and statuses read **Met**, **Below target**, **In progress**, **Not enough meetings yet** and **No policy**.
- **Last month report period**, for the whole previous calendar month, in reports and the Leaderboard.
- **Hours and minutes (H:MM)** display for every duration column, also used in CSV exports.
- **Private reports.** Reports only you can see are now called **Private** instead of Personal. Existing reports keep working.
- **Outreach update.** The official Outreach plugin can publish Events to Google Calendar and Discord separately, shows the Discord logo, and backs off when Discord rate-limits it.
- **For plugin authors:** module SDK 1.6.0 adds the shared CSV import kit (1.4), `ReportingStartDateField` (1.5) and scheduler steps (1.6), and `services.discord.retryAfterMs()` for rate limits.

## Features removed

None.
