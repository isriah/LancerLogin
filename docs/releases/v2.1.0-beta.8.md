# LancerLogin v2.1.0-beta.8

This beta lets members check in before a meeting starts and stops a busy team from locking itself out of sign-in. A new **Early arrival allowance** opens scans 15 minutes before each meeting by default, and an early arrival keeps its own scan time, so it never counts as late. Sign-in, kiosk pairing and first-time setup limits now apply to each visitor instead of the whole installation. **Find newest release** in **Settings > Modules** no longer reports a GitHub cooldown on the first try, and the official Outreach plugin can import activities from a CSV file.

## Updating to this release

- **Scans open 15 minutes before every meeting after the update.** The update sets the new **Early arrival allowance** to 15 minutes for existing installations. To keep refusing scans before a meeting starts, set it to 0 in **Settings > Modules > Attendance > Meeting configuration**.
- **Per-visitor sign-in limits start when the update finishes.** The update connects the dashboard to the server directly, with no action needed. If Cloudflare refuses the connection, the update still completes, the limits stay shared, and the update run's log shows the warning "Pages API binding not added". Check that the Cloudflare token has Cloudflare Pages: Edit, then run the update again.

## Bugs fixed

- **Sign-in no longer locks out a whole team.** The dashboard passed every visitor's requests to the server from one shared Cloudflare address, so the limits on password sign-in, kiosk pairing and first-time setup counted the whole installation as one visitor. About 30 sign-ins in 10 minutes, even with correct passwords, made everyone else see "Too many sign-in attempts. Wait a few minutes before trying again.", and anyone could cause that on purpose. Each visitor's network address now has its own limit, so only people on the same network, such as a school's, still share one.
- **Find newest release works on the first try.** In **Settings > Modules**, adding or upgrading a module could show "GitHub requires a cooldown before releases can be looked up" straight away, because other Cloudflare users had already used up GitHub's shared limit for anonymous requests. When the module selection credential is set up, release lookups, versions and module review now use it to get GitHub's much higher limit; without it they work as before. A refusal that is not a rate limit now says "GitHub refused the release lookup. Enter the commit you reviewed." instead of asking you to wait.
- **Backups name the plugin version that is actually installed.** When an update moved a plugin to a new version that changed none of its data, the installation kept recording the previous version, so backups listed that older commit for the plugin. The update to this release records Outreach v1.3.0 correctly.

## Features added

- **Early arrival allowance.** **Settings > Modules > Attendance > Meeting configuration** has an **Early arrival allowance** next to the **Late scan allowance**, from 0 to 180 minutes, 15 by default. A scan in that time before a meeting starts is an arrival for that meeting, shown at its own time (5:50 PM for a 6:00 PM meeting), and is not a late arrival. A scan earlier than that is refused as before.
  - Meetings now need the early arrival allowance plus the late scan allowance between them, 45 minutes with the defaults. Saving a meeting closer to another one is refused and names the meeting it overlaps, and **Import CSV** lists such rows as errors and skips them.
  - A longer allowance that would make upcoming meetings overlap is refused and names them. Meetings already saved closer together keep working; a scan that falls in both windows counts for the earlier meeting.
- **Outreach update.** The official Outreach plugin is now v1.3.0. **Import CSV**, just left of **Create activity**, adds up to 200 activities of any type from a file or pasted spreadsheet rows, with a preview of every row before anything is saved. **General** in Outreach's settings shows **Outreach reporting start date (operational baseline)**, so Outreach reports can start on a different date from Attendance's.

## Features removed

None.
