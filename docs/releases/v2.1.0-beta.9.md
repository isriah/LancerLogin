# LancerLogin v2.1.0-beta.9

This beta lets members sign in at a kiosk with a one-time code from Discord, and makes kiosks say why when a scan isn't taken, for example **Too early** or **No meeting today**. Turning on **Require PIN** no longer jams a Raspberry Pi kiosk's waiting scans, two-way Discord labels no longer take a role away from a member who has just linked their account, and syncing many Discord roles at once works on Cloudflare's free plan. The documentation now covers the whole 2.1 series, including web kiosks, privacy and updating from 2.0.

## Updating to this release

- **Update each Raspberry Pi kiosk after the dashboard.** A Pi kiosk keeps taking attendance on its old release, but Discord codes, the new notices and the kiosk fixes below arrive only with its own update (**Update kiosk** on **Manage kiosk**). Web kiosks update with the dashboard.
- **Update a Pi kiosk before turning on Require PIN for it.** **Require PIN** can now be turned on only for a Pi kiosk that reports release 2.1.0-beta.3 or later. Until then the checkbox is disabled with "Update this kiosk to turn on Require PIN." Kiosks that already have it on keep it, and web kiosks are never blocked.
- The update adds two small database changes for Discord codes and wrong-PIN reports. They are automatic.

## Bugs fixed

- **Require PIN no longer jams a Pi kiosk's queue.** Turning on **Require PIN** while a Pi kiosk had scans waiting to sync made the server refuse the first one forever, which held back every scan behind it. Scans taken before Require PIN was turned on are now recorded normally. A scan without a PIN taken afterwards is kept on the kiosk as a rejected scan for review, and the scans behind it keep syncing.
- **Syncing many Discord roles works.** **Sync all linked roles** and **Create labels from Discord roles** failed part-way with about 6 to 11 labels on Cloudflare's free plan, leaving some labels synced or linked and others not. They now work with many labels, and a failure no longer leaves them half done. Syncing one label, **Retry failed** and turning on two-way sync also stay within the plan's limits.
- **Editing a meeting's title or notes after updating.** The early arrival allowance added in beta.8 made some existing meetings overlap, and any edit to one of them was refused with "Meeting attendance windows cannot overlap". Only a change to a meeting's start or end time is checked now.
- **Offline wrong-PIN reports no longer loop or count twice.** A kiosk reporting about 20 or more wrong PINs after being offline could fail, resend the same report without end and count the same tries again, which could lock members out. A report is now applied once, whatever its size.
- **Discord codes and PINs hold up under fast guessing.** Guesses sent at the same moment could slip past the wait after 5 wrong PINs or codes. Each try is now counted before it is checked.
- **A failed meeting import says so.** **Import CSV** now shows "Import failed." with the reason when the final import fails, instead of nothing.
- **No false alert for inactive Operators.** **Accounts and roles** shows "None while inactive" in the Modules column for an inactive Operator instead of "Unavailable" and a red alert.
- **Unsaved reports show their filters.** A new report shows its period and every filter that applies, such as **Roster: Active members**, as chips you can remove, before its first save.
- **Set member PIN returns to the start screen.** On a web kiosk, **Done** (previously "Back to maintenance") and **Cancel** now leave maintenance, so the next member doesn't find it open. Maintenance screens also close after 60 seconds with no tap or key.
- **A web kiosk no longer forgets its pairing by mistake.** Any sign-in error from the network, for example a Wi-Fi login page, used to unpair the kiosk and drop its waiting scans. Only the server's own answer that the kiosk was retired or replaced does that now.
- **A web kiosk that hits an error can recover.** It shows **This kiosk hit a problem** with **Reload kiosk**, and stays paired with its waiting scans.
- **A Pi kiosk no longer shows the backup method while the server is reachable.** A scan the server refused could make a Discord code kiosk act as if it were offline.
- **The installer finishes when Cloudflare refuses the dashboard connection.** A refused Pages API binding used to stop **Install or upgrade LancerLogin** after the server was deployed but before the dashboard. It is now the warning "Pages API binding not added" and the dashboard is still deployed. The update's version of that warning no longer says to run the update again, which could not work: fix the token's Cloudflare Pages: Edit permission, and the next update adds the connection.
- **Deleting the entire installation removes scan-check records.** Records behind **Scan again** and re-enrollment suggestions were left behind.
- **Member search kiosks keep their setting.** Saving another change on **Identification** could switch a **Member search** kiosk back to member ID entry.
- **Role sync progress stops retrying forever.** When the Labels page can't check a running sync, it now backs off, stops after five failed checks and shows the error with **Check again**.
- **Retrying a half-saved member.** When adding or editing a member saved the member but not the attendance start date, the error now says what was saved, and trying again sends only the missing part.
- **Smaller fixes.** Web kiosk **Diagnostics** no longer lists Network, Last Wi-Fi scan and Uptime; command notices say a web kiosk receives a command "within ten seconds"; the report period reads **Current month**; and Settings uses **Module management credential** throughout.
- **Documentation.** The documentation site and reference pages now describe web kiosks, member search, PINs, Discord codes, scan checks, two-way labels, FIRST team lookup, what a kiosk receives, and [updating from 2.0 to 2.1](https://isriah.github.io/LancerLogin/updates.html#from-2-0).

## Features added

- **Discord codes at the kiosk.** A member runs `/code` in your Discord server, gets a six-digit code only they can see, and types it at the kiosk. No member ID or PIN is needed. Choose **Discord code** under **Manage kiosk > Identification** on a web kiosk or a Pi kiosk set to **Member ID entry**. It needs the Discord integration and each member's account linked with `/pair`.
  - A code works once and expires after 2 minutes. Only a recorded scan uses it up, so after a notice such as **Too early** the same code still works. After 5 wrong codes in a row the kiosk makes everyone wait 30 seconds, then 1 minute, then 5 minutes.
  - Codes need a network connection. **Backup method** chooses **Member ID** or **Member search** for when codes can't be used, **Offer the backup** chooses **Only when the kiosk is offline** or **Any time** (a **No code?** button), and **Require PIN for the backup method** adds a PIN to backup scans.
  - A Pi kiosk never sends a code ahead of scans still waiting to sync. Until they have synced it shows the backup method with "Discord codes are paused while earlier scans sync."
  - Entire-installation backups include each kiosk's Discord code settings, never the codes.
- **Kiosks say why a scan wasn't taken.** Instead of "Scan needs help", Pi and web kiosks show **Too early** with the time scans open, **Meeting ended** with the time they closed, **No meeting today**, **Already done** or **Not started yet**, on an amber screen for 5 seconds.
- **Two-way labels keep a newly linked member's role.** The first time a member is checked after linking their Discord account, nothing is removed: a member who already holds the role gets the label, recorded as a change from Discord, and a member with the label gets the role.
- **Unlink a retired label's role.** A retired label shows "Linked to Discord role" with **Unlink role**, so the role can be used for another label.
- **Require PIN only where it works.** **Require PIN** can't be turned on for a Pi kiosk too old to ask for PINs, which would have stopped that kiosk recording anything.

## Features removed

None.
